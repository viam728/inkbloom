# 施工简报：从「点状生成」到「闭环创作 Agent」

> 日期：2026-09-01
> 背景：AI 起稿已能生成章节正文并落库（P1），但用户指出 5 个体验/架构缺陷。
> 本简报把它们收敛为一条主线，作为后续施工的蓝图。

---

## 一、五个缺陷的收敛

用户列的 5 个缺陷不是并列的，而是**同一条主线的五个切面**：

1. **缺陷1（文本格式）**：AIGC 正文无分段分行、无插图占位符 → 阅读差、后配图难。
2. **缺陷2（入口形态）**：AI 起稿是独立标签页 → 应融合进对话 + 按钮，做成 Skill/插件形态。
3. **缺陷3（数据孤岛）**：Agent 只生成文本，不绑定创作系统（设定/角色/图谱/伏笔）。
4. **缺陷4（参数与双向流）**：生成阶段设置应是动态滑条；Agent 应从系统拿数据跑，跑完更新回系统。
5. **缺陷5（概念脱节）**：Agent 没用系统已有的 AI 创作概念（设定、线索、知识图谱），要"化手动为自动"。

**主线**：把 AI 从「一次调用生成一段文本」升级为「**闭环创作 Agent**」——

```
读（从系统拿上下文：大纲/记忆/角色设定/知识图谱/伏笔）
  → 生成（按作者参数：章节数/每章字数/风格/是否自动沉淀）
  → 写回（自动沉淀：实体抽取入图谱、伏笔探测入线索、角色设定入库）
  → 校验（一致性报告）
  → 下一章（带着更新后的系统状态继续）
```

缺陷 3/4/5 是同一件事的三面：**数据绑定 = 读系统 + 写回系统**。
缺陷 1 是生成质量规范；缺陷 2 是入口交互。

---

## 二、现状盘点（为什么"手动"）

系统里**已经存在**整套 AI 创作概念，但都是**手动触发**的点状工具：

| 能力 | 现状 | 触发方式 |
| --- | --- | --- |
| 实体抽取入知识图谱 | `knowledge_service.ExtractFromChapter`（/api/knowledge/extract） | 作者手动点「抽取」 |
| 一致性校验 | `CheckConsistency`（/api/knowledge/check） | 手动 |
| 伏笔探测 | `ForeshadowService.DetectPlants`（/api/knowledge/foreshadows/detect） | 手动 |
| 伏笔回收 | `ScanChapter`（/api/knowledge/foreshadows/resolve） | 手动 |
| 角色/设定 | 存于 `novel_memory.items` JSONB（name/type/fields/relations） | 手动登记 |
| 大纲 | `novel_outline.acts` JSONB | 手动 |

而 `story_service.GenerateStage` 生成章节后，**只存了 stage_payload，没有调用任何上述能力**——这就是缺陷 3/5 的根因：能力都在，但没接进闭环。

---

## 三、目标架构：闭环创作 Agent

### 3.1 读系统（缺陷5 的前半）
`AgentContextService.BuildAgentContext` 当前只组装 `outline + memory + preceding_chapters`。
需扩展：把**知识图谱节点**、**未回收伏笔线索**也纳入上下文，让 AI 生成时"知道"已有世界观与埋线。

### 3.2 生成（缺陷1 + 缺陷4 的前半）
- 生成参数做成**结构化配置**（story_job.config JSONB）：章节数、每章目标字数、风格、是否自动沉淀、插图占位符开关。
- `chapter` 场景 prompt 强制：**段落分行**（空行分段）+ 在需要配图处输出 `[插图：画面描述]` 占位符。

### 3.3 写回系统（缺陷3 + 缺陷5 的后半，"化手动为自动"的核心）
`AdoptChapter`（作者采纳）之后自动触发"沉淀流水线"：
1. `ExtractFromChapter`：新实体/关系入知识图谱。
2. `DetectPlants`：新伏笔线索入库（供后续回收提醒）。
3. （可选）一致性校验报告回显。

这样作者"采纳一章"，系统自动沉淀设定/角色/图谱/伏笔——**手动 → 自动**。

### 3.4 校验（缺陷4 的后半）
`verify` 阶段调 `CheckConsistency`，把一致性报告存入 stage_payload，面板展示。

### 3.5 入口（缺陷2）
「AI 起稿」从独立标签页，改为对话输入区 + 号菜单里的一个 **Skill 动作**（触发后在工作流面板内交互，但入口收敛到对话内）。

---

## 四、落地顺序

1. **P2-a 生成质量**（缺陷1）：chapter prompt 分段 + 插图占位符规范。
2. **P2-b 数据绑定**（缺陷3/5 核心）：AdoptChapter 后自动沉淀（图谱抽取 + 伏笔探测）；AgentContext 读入图谱 + 伏笔。
3. **P2-c 参数化**（缺陷4）：story_job.config + 前端滑条。
4. **P2-d 入口**（缺陷2）：+ 号菜单融合。
