# 施工简报：以「作品选择」为中心的体验重构 + Agent 修复

> 日期：2026-09-01
> 背景：全本创作/对话 Agent 落地后，暴露 6 个体验与正确性问题。
> 本简报把它们收敛为「作品选择是第一公民」的主线 + 两个独立修复。

---

## 一、问题归因

| # | 问题 | 根因 |
| --- | --- | --- |
| 1 | 起稿页创建按钮灰色 | StoryWorkflowPanel `disabled={!currentNovel}`，未选作品即禁用 |
| 2 | 起稿 Agent 直接发起，未先选作品 | Agent 无「当前作品」前置，直接从零起稿 |
| 3 | 大纲/记忆内容消失，提示需选作品 | OutlinePanel/MemoryPanel 依赖 `currentNovel`，未选即空态 |
| 4 | 需「作品概览」页，删除按钮移到概览页 | 中央编辑区无概览视图；删除散落在列表 |
| 5 | Skill 应挂对话窗口头顶 + 多模态输入 + 附件挂对话头 | Skill 菜单在输入框底部，无附件/多模态 |
| 6 | Agent 报 `reasoning_content must be passed back` | DeepSeek thinking 模式要求回传 reasoning_content，此前被丢弃 |

## 二、主线：作品选择是第一公民

`currentNovel` 是全局创作上下文。所有面板（大纲/记忆/起稿/编辑）都应以它为锚：
1. **未选作品时**：给出统一的「选择或新建作品」引导（而非各自空态/灰色）。
2. **选中作品时**：中央编辑区默认显示「作品概览」（书名、简介、字数、章节数、删除入口），而非空白欢迎页。
3. **起稿 Agent**：必须先绑定当前作品（currentNovel）或让用户显式选择，才发起。

## 三、独立修复

1. **问题6（reasoning_content）**：ai-service `chat_with_tools` 提取并返回 `reasoning_content`；Go 端 Agent 循环回传 assistant 消息时带上；`AgentMessageHTTP` 接受该字段。
2. **问题5（对话头 Skill + 多模态）**：Skill 与附件按钮挂到对话窗口**头部**，输入区支持文本 + 附件（图片等）多模态。

## 四、落地顺序

1. reasoning_content 修复（已完成，独立提交）
2. 作品概览页（NovelOverview 组件，接入 EditorArea 空态）
3. NovelList 删除按钮 → 概览页；列表项点击进概览
4. 起稿 Agent 前置作品绑定（有 currentNovel 才继续，否则提示选作品）
5. 对话窗口头部挂 Skill + 附件/多模态输入

> 每步 build + 测试 + 记录 + 提交，不堆积。
