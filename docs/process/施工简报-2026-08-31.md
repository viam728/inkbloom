# 施工简报 · 2026-08-31

> 本轮目标：收尾 P1-b（会话持久化 / 数据回流），落地 E5 交互式微创作，修复体验缺陷。`docs/核心施工记录.md` 记录每项改动细节，本文只给结论与「是否需重构」的判断。

## 一、结论

**未发现需要中断重构的致命问题。** 已修复 3 个实际缺陷，均为局部改造，不涉及架构推翻。P1-b 至此闭环，读者侧从「只读孤岛」升级为「可互动的阅读体验」。

## 二、本轮修复的缺陷

1. **追更计数膨胀**：`Follow` 无条件 `IncFollowCount`，重复点追更导致 `follow_count` 虚高。已改为幂等（先查 `GetFollow` 再决定增减）。`UpsertFollow` 冲突更新还错误地把 `created_at` 重置，一并修复。
2. **桌面端重启掉登录**：refresh token 原本只存 kvstore（内存），重启即失效。已迁入持久化 `user_sessions` 表（A22），并附带 3 端上限与设备管理端点。
3. **`UpsertFollow` 写坏 created_at**：冲突更新列包含 `created_at`，重复关注会把「关注时间」写成零值。

## 三、遗留技术债（暂不致命，按优先级）

1. **阅读进度模型太粗**：`reading_progress` 每个 (user, work) 只存「最后位置」，无法精确计算「每章完成率」。当前 A23 用「每章当前停留人数」近似。若要精确完成率，需新增逐章进度事件表（建议与 E5 埋点同批）。
2. **定时发布无通知**：章节到点可见依赖 `scheduled_at <= now()` 过滤（正确），但追更读者收不到「新章上线」站内通知（A21 未做通知部分）。
3. **采纳闭环缺通知**：读者建议被采纳后，读者端无 WS 实时通知（采纳状态在再次打开互动侧栏时可见）。需复用现有 WS Hub 做用户定向推送。

## 四、本轮交付

- A22 会话持久化（`user_sessions` 表 + 设备管理端点）
- A23 阅读数据回流（作者侧 stats 端点 + `WorkStatsPanel`）
- E5 交互式微创作（`interactions`/`interaction_votes` 表 + 段落情绪点击 / 划线评论 / 点赞 / 作者采纳）
- 追更计数 bug 修复

`go build`/`go vet`/`go test`/`pnpm build` 全绿。
