## 图床鉴权（C11）

**背景**：备忘录点名"图床公开共享、无鉴权、无用户隔离"。核实：`/assets/files/*filepath` 挂在 `engine` 顶层、无任何鉴权中间件，`{base}/novels` 下所有文件公开可读。

**做了什么**（commit `232216a` + `477adb5`）：
1. **签名 URL 机制**：新增 `internal/pkg/signedurl`（HMAC-SHA256 绑定 userID+path+expiry，密钥取 JWT secret，`Sign/Verify/SignURL/ParseQuery`）。
2. **静态路由强制鉴权**：`serveAssetFile` 校验——有效签名 URL（`<img>` 场景）或有效 Bearer（API 场景）才放行，否则 403。
3. **URL 返回点签名**：立绘上传（portrait）、图片上传/列表（image）、AIGC 资产列表/详情（aigc）返回的 URL 一律 `SignURL`。
4. **签名端点**：`GET /api/v1/assets/sign?path=...`（auth 组内），供前端对存量/章节内嵌 URL 动态签名。

**验收**：`go build ./...`、全量 `go test ./internal/... -count=1` 全绿；新增 `signedurl` 3 个单测（round-trip / 防篡改 / SignURL 回环）。已 SSH 推送 `405f4c2..477adb5`。

**遗留（重要，需跟进）**：①**章节正文内嵌图片**存的是无签名 URL，`<img>` 无法带 Bearer，需前端渲染时走 `GET /assets/sign` 动态签名（或后端改写内容 URL），否则这些图会 403；②发布作品封面需对读者公开，签名 URL 24h 过期后读者可能加载失败——需发布流程用长 TTL 签名或公开路径；③同步导入导出对 `/assets/files` URL 的路径匹配需剥离签名参数。

## AI 对话停止中断 + 会话历史（C8）

**做了什么**：对话生成可「停止」；消息按会话持久化到 localStorage，支持新建/切换/删除会话。

**为什么**：原 Agent 对话是单次 POST，前端只有"打字中"指示器，无法取消；消息只存 zustand 内存，刷新即丢、无多会话。

**取舍与理由**：
- 停止用 AbortController（前端取消请求），不深改后端 Agent 循环——后端本就单请求，取消即不再渲染结果，成本最低且够用。
- 历史用 localStorage 而非后端会话表：C8 目标是"清空/恢复/多会话"的用户体验，本地持久化即可满足；后端持久化（跨设备）留待真正的多端同步一起做，避免为单个面板引入会话表。
- 会话标题取首条用户消息前 18 字，不额外让用户起名——零交互成本。

**验收**：`pnpm exec tsc --noEmit` 通过。已 SSH 推送。

## AI 起稿创作意图栏（C9）

**做了什么**：起稿配置卡（对话内）新增「目标受众 + 创作意图」两个字段，写入 `StoryJobConfig`，随生成设置进入 LLM 提示词。

**为什么**：备忘录要求"AI 起稿页增加创作意图栏（定受众/意图）"，此前未落地；受众/意图决定叙事取向与语感，是起稿质量的关键输入。

**取舍与理由**：
- 受众/意图做成**可选文本输入**而非预设枚举——创作意图自由度高，枚举反成约束。
- 「标题与创意由 AI 给出」暂不实现：需额外 AI 起名端点，且与现有"用户填创意→起稿"流程有交互冲突，留待后续单独做，不在本次意图栏里混入。

**验收**：`go build ./...`、`pnpm exec tsc --noEmit` 通过。已 SSH 推送。

## Agent 改写变更摘要（B7）

**做了什么**：`write_chapter` 返回字数变化（before/after）；agent 工具结果 JSON 由 handler 解析成结构化 map；前端 AI 消息工具徽章显示「撰写正文 · N→M 字」。

**为什么**：B7 指出 Agent 改写只返回最终文本、无 diff/摘要，作者看不到改写范围。

**取舍与理由**：
- 先做**字数变化摘要**（成本低、立竿见影），让作者至少感知改写幅度；
- 「逐字 diff + 确认/撤销」UI 较大，留待后续——撤销能力其实已由 Phase 1 快照 + chapter_versions 还原支撑，缺的是把 diff/还原接进对话流，可与现有 DiffViewer 复用。

**验收**：`go build ./...`、`pnpm exec tsc --noEmit` 通过。已 SSH 推送。

## 采纳闭环 WS 通知（D14）

**做了什么**：读者建议被作者采纳后，通过 WS Hub 向该读者实时推送 `notification` 帧。

**为什么**：D14 指出采纳后读者端无实时推送，追更/互动闭环断了最后一环。

**取舍与理由**：用 `WithNotifier` 回调注入（沿用 `StoryService.WithClosedLoop` 的 setter 先例）——service 不直接依赖 WS 层（避免 server↔service 循环依赖），由 main 把回调适配成 `WSMessage{Type:"notification"}`。只做"采纳"一个事件点，隐藏/点赞等按需再扩。

**验收**：`go build ./...` 通过。已 SSH 推送。
