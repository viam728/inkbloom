# 核心施工记录 2026-09-04：写作状态收敛两态 + 发布状态系统管理

## 需求

- 写作状态管理合并为 2 态：写作中（drafting）/ 已完成（done）。
- 节点页（大纲节点卡）把状态标签替换成 2 态切换按钮。
- 该切换按钮同时加到编辑器工具栏「发布」按钮左侧，用于切换当前章节状态。
- 发布状态由系统管理：章节发布成功后自动同步为「已发布（published）」，用户不可手改。

## 方案

写作状态两态（drafting/done）由用户切换；`published` 作为系统写入的第三态复用大纲节点
JSON 通道（无需新增后端端点）。legacy `planned`（未开始）读取时收敛为 drafting，写回后自然淘汰。

## 变更清单

### 前端

- `packages/web/src/stores/outline-store.ts`
  - `OutlineStatus` 收敛为 `'drafting' | 'done' | 'published'`；
  - `OUTLINE_STATUS_LABELS`：写作中/已完成/已发布；
  - 新增 `WRITABLE_OUTLINE_STATUSES`（用户可切的两态闭集）与 `toggleWritingStatus` 互切函数；
  - `addNode` 默认 `drafting`。

- `packages/web/src/components/outline/OutlinePanel.tsx`
  - NodeCard 状态标签 → 两态切换按钮（stopPropagation，不触发编辑弹窗）；
    published 节点按钮禁用，title 提示「发布状态由系统管理」；
  - 编辑弹窗状态行仅渲染两态按钮；published 显示静态「已发布」；
  - 进度统计与记忆章节锁判据均把 published 计入完成。

    数据源为 `currentChapter ↔ outline node.chapter_id` 绑定关系，点击经 `updateNode` 持久化。
- `packages/web/src/components/publish/PublishModal.tsx`
  - 发布章节成功（非定时）后，遍历大纲把对应 `chapter_id` 的节点状态系统写入 `published`；
    大纲未加载时先 `loadOutline` 再同步。

### 后端（Go）

- `packages/server/internal/service/outline_normalize.go`
  - 状态闭集新增 `published`；`planned` 作为 legacy 输入继续接受；
  - 非法/缺失 status 的缺省值 planned → **drafting**（两态模型新默认）。
- `packages/server/internal/service/novel_doc_service.go`：`appendChapterNode` 新节点默认 drafting，不再写 planned。
- 测试：`outline_normalize_test.go`、`outline_sync_integration_test.go` 的非法 status 回落断言 planned → drafting。

## 数据兼容

- 已发布节点回滚：取消发布 UI 当前未开放；若后续开放需在取消发布时把 published 回写 done。

## 补充：模型身份如实化 + 调用链确认（同日）

### 需求

- 模型回答自己的名字改为原生回答，不伪装身份。
- 确认 AI 模型切换与调用链正确——用户没有 OpenAI（GPT）配置，选择器不应出现 gpt-* 选项。

### 排查结论

- 身份伪装源：`agent_service.go` 的 agentSystemPrompt 只写「你是 InkBloom 的创作 Agent」，
  未告知底层模型，模型被问「你是谁」时可能虚构/伪装名字。
- gpt-* 选项来源：`ModelSelector.tsx` 硬编码了 `gpt-4o / gpt-4o-mini`，但 .env 只有
  DeepSeek key（默认端点 api.deepseek.com）+ 智谱 GLM key，没有 OpenAI 配置，
  选了必失败/误导。

### 变更

1. `packages/web/src/components/ai/ModelSelector.tsx`：移除 `gpt-4o / gpt-4o-mini` 选项，
   注释说明未配置 OpenAI key。
2. `packages/server/internal/service/agent_service.go`：Run() 按当次请求的 model 注入身份指引——
   「你由模型 {model} 驱动；被问你是谁/什么模型时，如实以原生名称回答（如 GLM、DeepSeek），
   不要自称 GPT/ChatGPT 等其他产品，不要伪装或虚构名字」。

### 验证（重启 ai + go 后直测 ai-service /api/agent/chat）

- `model=glm-4.5-air` → 智谱端点，回答「我是GLM模型。」✓
- `model=deepseek-chat` → DeepSeek 端点，回答「我是DeepSeek，由深度求索公司创造的原生模型。」✓
- 路由代码复核：`openai_provider.py` 的 chat / chat_with_tools / stream 三处均走 `_client_for(model)`，
  glm-* → 智谱，其余 → 默认 DeepSeek 端点。
- `tsc --noEmit`、`go build ./...` 通过；服务经 start-dev.ps1 -Stop / -Build 重启健康。

## 补充 3：身份如实化下沉到 ai-service 层，覆盖全部对话端点（同日）

### 问题

用户反馈「调用 api 还是没有返回模型真名」。上轮身份指令只加在 Go 侧
`agent_service.go` 的 Agent 路径，且该注入代码又被外部回退。排查发现：

- 前端 AI 对话面板 `sendMessage` 实际走 `agentChat → POST /api/v1/agent/chat →
  Go AgentService → ai-service /api/agent/chat`；
- 而 `/api/chat/stream|complete|inline|rewrite` 等普通对话端点、以及
  `/api/agent/chat` 端点，system prompt 里都没有「如实回答原生名字」的指令；
- `agentSystemPrompt` 只说「你是 InkBloom 的创作 Agent」，模型被问「你是谁」时
  会答产品名「InkBloom 创作 Agent」或幻觉成 GPT，而非原生模型名。

### 修复：身份注入统一收敛到 ai-service HTTP 层

`packages/ai-service/app/main.py` 新增 `_IDENTITY_HINT` 与幂等辅助函数
`_with_identity(messages, model)`——把「你由模型 {model} 驱动；被问名字时如实以
原生名称回答（GLM/DeepSeek），不要自称 GPT/ChatGPT，不要伪装」追加到首条 system
消息末尾（无 system 时插入一条）。应用到**全部 5 个作者可对话端点**：

- `/api/chat/stream`、`/api/chat/complete`、`/api/chat/inline`、`/api/chat/rewrite`、
  `/api/agent/chat`。

知识抽取（entity/relation/consistency/foreshadow）、图像 prompt、AI action 场景生成等
**机器调用端点不经此层**（它们要求严格 JSON、从不被问身份），避免污染输出。

`packages/server/internal/service/agent_service.go`：移除（此前被回退的）Go 侧重复注入，
改为注释说明「身份由 ai-service `_with_identity` 集中注入，勿在此重复」——单一事实来源，
model 名以 ai-service 解析值（含 default 回退）为准。

### 顺带修复：rewrite 场景模型未透传

`packages/web/src/stores/ai-store.ts` `triggerRewrite` 调用 `streamRewrite` 时漏传
model（inline 已传）。补 `resolveSceneModel('rewrite')`，使改写跟随所选模型——
这也是「模型切换未生效」的一个实例。

### 验证（重启 ai+go 后直测 ai-service，含真实链路人设）

- `/api/chat/complete`：`glm-4.5-air` → 「我是GLM模型。」；`deepseek-chat` →
  「我是由深度求索（DeepSeek）公司开发的DeepSeek模型。」✓
- `/api/agent/chat`（带「你是 InkBloom 创作 Agent」人设，模拟前端真实链路）：
  问「你叫什么名字？你是 GPT 吗？」→ 「我是GLM模型，不是GPT。」✓
- 幂等：`_IDENTITY_HINT` 已存在时不重复追加。
- `python -c ast.parse`、`go build ./...`、`tsc --noEmit` 通过。
- 注：GLM-4.5 默认动态思考，`max_tokens` 过小（如 60）会被思考耗尽导致 content 空，
  实测需 ≥ 数百；生产对话链路 max_tokens=2048 不受影响。
- 过程遇到 go server 启动 `nats: filtered consumer not unique`（已知问题），
  `docker restart inkbloom-nats` 后恢复。
