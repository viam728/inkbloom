## 1. 批量发布只生效一章 — 根治（前端拦截器）

**现象**：发布管理多选勾选多章，实际只发布第一章，循环中断。

**根因**：`api-client.ts` 响应拦截器把业务码 `code !== 200` 一律判失败。而
`POST /publish/works/:wid/chapters` 返回 **201 Created** → 第一发即被前端
reject，循环中止；后端那一章实际已入库，造成"勾多章只发一章"。

**修复**：
- `api-client.ts`：非 2xx（`code < 200 || >= 300`）才算业务错误，201 正常解包。
- `PublishModal.handlePublishChapters`：逐章串行 + 单章失败不中断整批，
  汇总"成功 N 章 / 未推送 M 章"反馈，失败项保留勾选便于重试。

## 11. AI 记忆访问闸门：3 软闸 + 3 硬闸（备忘录规格落地）

### 需求

记忆条目新增六种 AI 访问权限（编辑器内单选，默认全部关闭=不限制）：

| 闸门 | 模式 | 语义 |
| --- | --- | --- |
| 软闸 | `ignore` AI全局忽略 | 注入但要求忽略，除非人类指令明确提及 |
| 软闸 | `restricted_visible` AI限制可见 | 单选解锁章，该章及以后可见；此前视为不可见，绝对不能剧透/提前显露，允许伏笔或隐晦线索 |
| 软闸 | `partial_visible` AI局部可见 | 多选可见章，选中章可见、其余不可见；同样禁剧透、允许伏笔 |
| 硬闸 | `disabled` AI全局禁用 | 绝不向 AI 注入该条目 |
| 硬闸 | `restricted_disabled` AI限制禁用 | 单选解锁章，该章及以后才注入 |
| 硬闸 | `partial_disabled` AI局部禁用 | 多选注入章，仅选中章注入 |

### 服务端求值（Go，唯一权威）

- `agent_context.go`：新增 `agentMemoryAccess`（mode + unlock_chapter_id +
  visible_chapter_ids，引用大纲节点 id）与 `resolveMemoryItems`——按写作位置

  - 硬闸位置不符**直接丢弃**，绝不进 payload（唯一绝对保证）；
  - 软闸照常注入，附 `access` 指令（`ignore`/`hidden` + Go 渲染的中文约束
    说明，Python 只负责打印）；
