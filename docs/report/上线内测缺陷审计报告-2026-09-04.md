### 阶段二：内测体验兜底（建议 1–2 周，P1 优先）

- **数据安全三件套**（最高优先）：`beforeunload` 二次确认 + 草稿 IndexedDB 本地兜底 + 保存失败 toast 与指数退避重试 + 顶部「离线未保存」常驻横幅
- **401 优雅降级**：登出前 flush 脏草稿到 localStorage，弹「登录已过期，草稿已暂存」
- **编辑器性能**：`shouldRerenderOnTransaction:false`，HTML/字数统计节流 300ms 并改增量统计；自动保存后不再全量 `fetchChapters`
- **AI 交互反馈**：Agent 调用改 SSE 流式并展示「已用 12s · 正在撰写正文」与工具执行步骤；SSE 增加独立 `onError` 通道（错误串不再污染正文）；`AbortController` 支持中断；所有 `catch {}` 补 toast + 重试入口
- **全局兜底**：根组件加 ErrorBoundary、`main.tsx` 注册 `unhandledrejection`/`window.onerror`
- **Agent 韧性**：接入 `token_counter` 做预算裁剪 + 前文滑窗；显式 `timeout=` 与 `asyncio.wait_for` 总时限；`max_retries=1` + 熔断器 + 按用户信号量限流；建模型优先级链做多模型降级；`/health` 拆 `/healthz` + `/readyz`
- **抽取器语义**：entity/relation/consistency 复用 foreshadow 的 `degraded=true`，让 Go 侧区分「AI 故障」与「确实没结果」
- **后端一致性**：`Restore` 包 `db.Transaction`；启动期孤儿章节清理改为版本化一次执行 + 返回 error + 删除前备份；engine 重试 `select ctx.Done()` + 并发信号量；忽略的 DB error 全部接收并上报指标
- **密钥治理**：`.env` 迁到 Secret Manager，异常与日志脱敏

### 阶段三：内测前工程加固（建议 2–3 周）

- **日志脱敏**：对 `/ws`、`/assets/sign` 的 query 做 `token/sig/password` 黑名单过滤
- **补齐 P1 后端项**：补偿退款重试表、发布 slug 捕获 23505 后 `resolveSlug` 重试返 409、`admin_repo` 状态改 int16 白名单、`portrait` 归属校验

- **仓库瘦身**：`.gitignore` 补 `*.exe`、`*.db`、`*.log`、`dist/`；`git rm --cached` 清理已入库产物并轮换所有泄露密钥
- **可观测性**：结构化日志 + `X-Request-ID` 跨 Go↔Python 透传；接入 Sentry；补 `/healthz`/`/readyz` 与关键指标（任务积压、AI 失败率、扣费失败数）

- **文档**：补部署 runbook、回滚预案、内测反馈收集模板

## 七、值得保留的优点（勿在重构中破坏）

1. **Repository 层强制用户域**：`scope.ForUser` + 全 repository 带 `user_id` 谓词，IDOR 整体防线扎实（仅 `GetByID` 单点遗漏）
2. **计费一致性设计正确**：`token_repo.go` 乐观锁版本 + CHECK 约束 + 单事务写流水；支付用 `MarkPaid` 条件更新做幂等单交付
3. **SQL 全参数化**，无字符串拼接；上传有 MIME + 扩展名双白名单、大小上限、zip-slip 防护
4. **`extract_json()`**（`ai_actions/service.py:93-122`）围栏正则 + 括号切片 + 类型收窄，是仓库内最健壮的解析兜底，应全量复用
5. **`degraded=true` 语义**（`main.py:352-389`）正确区分「AI 故障」与「确实没有结果」，是应向全部抽取器推广的正确方向
6. **前端自动保存三重 flush**：per-tab 独立防抖 + 切 tab / 关 tab / 卸载三重落盘；AI 改写落库前强制 `snapshotChapter` 存点
7. **鉴权链路健壮**：401 单飞续期、402 按 message 分流弹窗并 3s 节流；config 层 cloud 模式拒绝占位 JWT secret、local 模式随机生成
8. **迁移规范**：48 个 SQL = 24 组完整 up/down
