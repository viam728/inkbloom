## 一、项目概况

**InkBloom** —— 面向自媒体创作者与小说作者的 AIGC 图文创作工具。

- 前端：React 18 + TypeScript + Vite + TipTap + Tailwind
- 后端：Go + Gin + GORM + gRPC
- AI 服务：Python + FastAPI（DeepSeek）
- 数据：PostgreSQL 16（云端）/ SQLite（桌面端）+ Redis + NATS JetStream
- 形态：Web（`packages/web`）+ Electron 桌面端（`packages/desktop`）+ Go 服务（`packages/server`）+ AI 服务（`packages/ai-service`）+ 共享契约（`packages/shared`）

## 三、发现的问题清单

### A. 正在施工（未闭环）

1. **Phase 3 整本快照后端未提交**：`novel_versions` 全链路代码已写完（含单测），但停留在工作区未 `commit`，且未跑 `go build/vet/test` 验证装配（`main.go`/`database.go`/`http.go` 装配是否完整需确认）。
2. **Phase 3 前端缺失**：整本版本历史/里程碑/还原的 UI 未实现，作者无法通过界面"存里程碑 → 一键还原整本"。

### B. Agent 正确性与健壮性（源自 `agent-e2e-reddots.md` 剩余边角）

3. **`write_chapter` 整章覆盖无模式**：默认 `replace`，无 `append`/`merge`。作者说"续写/扩写"会被当成整章重写，覆盖风险仅靠 Phase 1 快照兜底，语义上仍是错的。
4. **`write_chapter` 存在性检查在 LLM 生成之后**：传错 `chapter_id` 会先白跑一次 LLM 生成才报错，浪费 token（应前移到生成前）。
5. **R1 大纲去重边角**："第一章 觉醒" 与 "第二章 觉醒" 去序数后同为 "觉醒"，会被**误合并**。正解是把"章/回"序数从 `outlineTitleKey` 剥离规则拆出，只剥幕/卷/部/篇，`GetChapterByTitle` 另用独立的章序数 key。
6. **测试缺口**：`write_chapter` not-found 路径、`list_chapters` 工具未单测。
7. **Agent 变更预览缺失**：Agent 重大改写只返回最终文本，无 diff/摘要返回，前端无"确认/撤销"交互，作者对改写范围不可控。

### C. Agent 产品功能欠账（源自 `备忘录.md`）

8. **AI 对话无停止中断、无历史管理**：对话流式生成无"停止"按钮，也无会话历史管理（清空/恢复/多会话）。
9. **AI 起稿手动页缺陷 + 创作意图栏未做**：`StoryWorkflowPanel` 仍存在逻辑缺陷；备忘录要求"AI 起稿页增加创作意图栏（定受众/意图，标题与创意由 AI 给出）"未落地。
10. **附件多模态理解未接入**：附件当前仅把文件名随消息传给 Agent、由 AI 返回信息处理，未做真实的文件内容（图片/文档）多模态理解。
11. **图床公开共享、无鉴权无用户隔离**：备忘录明确提出"图床居然是公开共享的，没有鉴权，没有区分用户吗？"——存在素材越权访问隐患，需确认 assets 访问是否按 user 隔离。

### D. 阅读/发布遗留技术债（源自 `施工简报-2026-08-31.md`）

12. **阅读进度模型太粗**：`reading_progress` 每 (user, work) 只存最后位置，无法精确计算每章完成率（当前用"每章停留人数"近似），需新增逐章进度事件表（建议与埋点同批）。
13. **定时发布无站内通知**：章节到点可见依赖 `scheduled_at <= now()` 过滤，但追更读者收不到"新章上线"通知。
14. **采纳闭环缺 WS 通知**：读者建议被作者采纳后，读者端无实时推送（需复用 WS Hub 做用户定向推送）。

### E. 商业化占位 / 未接入

15. **真实支付（G10）与真实短信（G11）**：支付宝/微信支付、短信通道均为占位 stub（需企业资质）。
16. **桌面端自动更新**：为骨架实现，更新 feed URL 为占位地址，未配置真实更新通道。
17. **多平台构建（G19）**：macOS/Linux 桌面端构建未做（需证书与 CI）。
18. **封面字段已存在但发布面板无封面上传入口**；发现页无推荐算法/分类（仅按更新时间倒序）。
