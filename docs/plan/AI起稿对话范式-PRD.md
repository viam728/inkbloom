## 1. 背景与产品目标

### 1.1 背景

InkBloom 当前的 AI 起稿走的是"表单面板"范式：用户在右栏 StoryWorkflowPanel 中手动填创意、拖滑动条、点创建，配置随 createJob 一次写入后不可改；产物（各阶段内容）在面板内展示，仅有一个"采纳到章节"按钮，且 adopt 存在撞 key、无幂等等缺陷。

与此同时，Agent 对话窗（AIChatPanel）已具备消息列表、Skill chips、一体化输入区，但 Skill 点击行为只是把 prompt 拼进输入框（确定性拼接），消息气泡（MessageBubble）为纯文本 + 工具徽章，**没有任何按钮/卡片交互**。也就是说：对话窗与创作流水线是两条互不相通的路。

Claude Code / Codex 式对话范式的核心定义是：**工具的执行、参数确认、结果展示、后续动作，全部发生在对话流内，AI 消息本身是可交互载体**。用户不需要在"对话"与"面板"之间来回切换，配置面板以卡片形式出现在消息流里，按钮操作就地完成闭环。

### 1.2 产品目标

1. **对话内闭环**：从"AI 起稿"调起 → 参数配置（滑动条）→ 确认 → 进度 → 结果 → 采纳/重生成/放弃，全程在对话窗内完成，不打断对话上下文。
2. **保留现有流水线**：后端 story_jobs 状态机不改，前端复用现有 REST 端点；本 PRD 是"范式迁移"，不是"重写流水线"。
3. **修复采纳链路已知缺陷**：adopt 幂等 / 撞 key 问题在本期一并解决（后端小改）。
4. **可扩展的卡片机制**：本期只做起稿两张卡片（配置卡 + 结果卡），但消息卡片机制是通用的，后续 polish / outline 等 skill 可复用。

### 1.3 成功指标（定性验收）

- 用户可以在对话窗内完成一次完整起稿并采纳到章节，全程不打开右栏面板。
- 配置卡片上的滑动条范围与现有 StoryWorkflowPanel 完全一致（章节数 3–50 默认 10；每章字数 500–5000 step 100 默认 2000）。
- 同一章节重复点击"采纳"不产生重复章节（幂等）。

## 2. 用户故事

| # | 故事 | 验收要点 |
|---|------|----------|
| US1 | 作为作者，我在对话窗点击 Skill"AI 起稿"后，对话流中立即出现一张**配置卡片**（创意 textarea、标题、两条滑动条、文风、auto_settle 勾选），我可以就地修改参数。 | 点 skill 后卡片插入消息流；滑动条范围/默认值与旧面板一致；卡片可反复编辑直到点确认。 |
| US2 | 作为作者，我在配置卡片上拖动"全书章节数"和"每章字数"滑动条并确认后，系统直接创建 story job 并开始起稿，我**不需要打开右栏面板**。 | 点"开始起稿"后前端直调 createStoryJob（携带卡片参数）；卡片变为"进行中"态；旧面板中能看到同一 job（双入口数据同源）。 |
| US3 | 作为作者，起稿进行中时，我能从对话窗的结果卡片/进度态看到当前阶段（outline → plan_chapters → draft_chapter…），并等待完成。 | 进行中卡片展示阶段名与简单进度提示（P1 轮询刷新；P0 至少展示"已提交，正在生成"占位态）。 |
| US4 | 作为作者，起稿完成后，对话流中出现**结果卡片**，展示产物内容摘要，并携带按钮：生成下一阶段 / 采纳到章节 / 重新生成 / 放弃。 | 四个按钮按 job 状态/阶段条件渲染；内容预览可展开；按钮操作有 loading 态与结果反馈。 |
| US5 | 作为作者，我对某一章结果不满意时，点击"重新生成"，系统在原地重跑该阶段，卡片内容更新，且不会产生重复章节。 | 重新生成复用 generate 端点；重生成后原卡片内容被替换或追加新卡片（见 Q4）。 |
| US6 | 作为作者，我改变主意不想继续这稿了，点击"放弃"，卡片变为终止态，不再继续推进流水线。 | 放弃调用 delete/终止逻辑；卡片呈灰色终态；该卡片按钮全部禁用。 |
| US7 | 作为作者，我点击"采纳到章节"后，该章内容写入作品章节列表，并得到明确的成功/失败反馈。 | adopt 走幂等修复后的端点；重复点击不产生重复章节（后端按 job+章节校验）；成功后卡片标记"已采纳"。 |
| US8 | 作为作者，当 job 处于 failed / paused 状态时，结果卡片能呈现对应状态分支（如"生成失败：重试 / 放弃"），而不是永远转圈。 | failed 态卡片展示错误提示 + 重试按钮；paused 态展示继续/放弃（P1）。 |

## 3. 需求池

### P0（本期必须）

| 编号 | 需求 | 一句话验收标准 |
|------|------|----------------|
| P0-1 | **消息卡片机制**：`AIMessage` 增加可选 `card` 字段（类型 + payload + 状态），`MessageBubble` 增加卡片渲染分支。 | 一条带 card 的消息在气泡内渲染出结构化卡片（而非纯文本），无 card 的消息渲染不受影响。 |
| P0-2 | **DraftConfigCard（起稿配置卡片）**：点击 skill "story" 不再只拼 prompt chip，而是直接在对话流插入配置卡片：创意/标题输入 + 章节数滑动条（3–50，默认 10）+ 每章字数滑动条（500–5000，step 100，默认 2000）+ 文风 + auto_settle 勾选 + "开始起稿"按钮。 | 点 skill 后消息流内出现可编辑卡片；参数与旧面板一致；确认后调 createStoryJob 成功创建 job。 |
| P0-3 | **确认后直调流水线**：卡片确认后前端复用 `services/story-client.ts` 现有端点（createStoryJob / generate / advance / adopt），后端状态机零改动。 | 创建的 job 在旧 StoryWorkflowPanel 中同样可见可操作（数据同源）。 |
| P0-4 | **DraftResultCard（结果卡片）**：产物以结果卡片呈现在 AI 消息里，携带按钮：生成下一阶段 / 采纳到章节 / 重新生成 / 放弃；按 job 阶段与状态条件渲染。 | 每个 job 阶段产出一类结果卡片；按钮可用性与 job 状态一致；点击按钮触发对应端点。 |
| P0-5 | **adopt 幂等修复（后端小改）**：adopt 端点按 job + 章节标识校验，拒绝/忽略重复采纳，不再依赖前端拼 `ch-${n}` 造成碰撞。 | 同一章节重复采纳不产生重复章节；后端返回明确错误码，前端卡片有失败提示。 |
| P0-6 | 卡片基本状态机：配置卡（编辑中 → 已提交）与结果卡（进行中 → 完成 → 已采纳 / 已放弃）至少覆盖这些态。 | 每个状态下按钮与视觉呈现符合 §4 交互说明，无未定义态。 |

### P1（本期尽量）

| 编号 | 需求 | 一句话验收标准 |
|------|------|----------------|
| P1-1 | 卡片进行中状态轮询刷新：结果卡进行中时定时拉取 job 状态并刷新卡片（阶段名/进度）。 | job 完成/失败后卡片在轮询间隔内自动更新为终态，无需用户手动刷新。 |
| P1-2 | 卡片操作回发上下文消息：卡片按钮操作后，回发一条轻量 user 消息（如"已采纳第 3 章"）保持对话上下文（是否必要见 Q5）。 | 每次卡片操作在消息流中留下可读的轨迹消息。 |
| P1-3 | failed / paused 状态卡片分支：失败卡片带错误摘要 + 重试/放弃按钮。 | job failed 后卡片显示错误态；点重试重新触发该阶段。 |
| P1-4 | 配置卡片回填编辑：已提交的配置卡片可"复制参数再起一稿"。 | 点复制后生成一张新的可编辑配置卡，参数预填。 |

## 4. UI 交互说明

### 4.1 卡片在消息流中的位置与形态

- 卡片渲染在 **AI 消息气泡内**（MessageBubble 分支）：外层仍是现有暗色气泡容器（`bg-[?]` 圆角、边框沿用 AIChatPanel 暗色系），内部以卡片区块呈现，与纯文本气泡视觉区分靠"标题栏 + 结构化控件 + 主操作按钮"。
- 推荐使用系统态弱化处理还是 assistant 侧渲染见 **Q2**（推荐 assistant 侧，改动最小）。
- 卡片与 Skill chips / 输入区无耦合：卡片在消息列表区域，输入区行为不变。

### 4.2 DraftConfigCard（配置卡片）

- 结构：卡片标题栏（icon + "AI 起稿 · 配置"）→ 作品名 input → 一句话创意 textarea → 两条滑动条（右侧数值实时显示）→ 文风 input → auto_settle checkbox → 底部主按钮"开始起稿"。
- 滑动条规格与旧面板一致：章节数 3–50 默认 10；每章字数 500–5000 step 100 默认 2000。
- 按钮态：编辑中（主色可点）→ 提交中（disabled + spinner）→ 已提交（卡片折叠为只读摘要条，点击可展开回看参数）。
- 校验：创意为空时"开始起稿"disabled；不引入新校验规则。

### 4.3 DraftResultCard（结果卡片）

- 结构：标题栏（阶段名 + job 状态 badge）→ 产物内容预览（默认折叠，最多显示若干行，可展开）→ 按钮组。
- 按钮组（条件渲染）：
  - **生成下一阶段**：阶段未到最后时可用；
  - **采纳到章节**：章节产物（draft/verify/finalize 产物）可用，已采纳后变为"已采纳 ✓"disabled；
  - **重新生成**：非进行中态可用；
  - **放弃**：非终态可用，确认后卡片灰化，全部按钮禁用。
- 进行中态：内容区显示 spinner + 当前阶段文案（P0 静态文案，P1 轮询更新）。
- failed 态：红色 badge + 错误摘要 + "重试 / 放弃"（P0 先展示占位错误态，重试逻辑 P1 补齐，见 Q 待议）。

### 4.4 与现有元素的视觉关系

- 颜色/间距/圆角全部复用 AIChatPanel 现有 Tailwind 暗色 token，不新增设计变量。
- 工具执行小徽章（toolExecutions）保留在卡片上方/下方，卡片可视为徽章的"结构化升级"。
- 消息无持久化的现状本期不改（卡片随会话内数组存活）。

## 5. 非目标（本期不做）

1. **SSE / 流式输出**：agent chat 仍为单次 POST，流式改造单列为 P2。
2. **附件真正上传**：附件 chips 仍为前端展示。
3. **Agent 意图识别返回卡片**：卡片由前端确定性触发（点 skill 即插卡），不走 LLM 意图识别（理由见 Q1）。
4. **对话消息持久化**：消息与卡片仍存于前端内存。
5. **后端状态机重构**：不改 idea→…→done 状态机，不改 generate 同步请求模型（轮询属 P1）。
6. **DraftPreviewModal 两链路联动**：仅列 P2。
7. **竞品分析 / 市场分析**：本 PRD 不含。

## 6. 待拍板问题

| # | 问题 | 选项 | 推荐 | 理由 |
|---|------|------|------|------|
| Q1 | 配置卡片触发方式 | A. 点 skill "story" 立即在对话流插入配置卡片；B. 发消息后由 agent 意图识别返回卡片 | **A** | 纯前端确定性，行为可预期、零后端改动；B 需后端意图协议与多轮确认，成本高且不稳定 |
| Q2 | 卡片消息渲染位置 | A. 渲染在 assistant 消息侧（AIMessage.card）；B. 独立系统态/system 消息类型 | **A** | 复用现有消息模型与气泡容器，改动最小；系统态需新增 role 与渲染规则 |
| Q3 | 旧 StoryWorkflowPanel 右栏 Tab 去留 | A. 本期保留双入口（面板 + 对话卡片数据同源）；B. 收编下线面板 | **A** | 新范式需验证期，双入口互为兜底；收编可待卡片链路稳定后下期处理 |
| Q4 | 采纳粒度 | A. 单章采纳（维持现状语义）；B. "采纳全部"按钮循环跑完剩余章节 | **A** | 单章语义清晰、与幂等修复天然契合；批量采纳引入长耗时与失败中途处理复杂度，可后补 |
| Q5 | agent 是否感知卡片操作（回发上下文消息） | A. 需要：每次操作回发轻量 user 消息；B. 不需要：卡片操作不进对话流 | **A（P1）** | 回发让后续对话能接上下文（"刚才那章再润色下"才成立），成本极低；但可放 P1，P0 先保证闭环 |
| Q6 | 重新生成的产物呈现 | A. 原卡片内容原地替换；B. 追加一条新结果卡片保留历史 | **A** | 对话流不膨胀；历史版本可通过章节列表回看；若用户要对比再议 |
