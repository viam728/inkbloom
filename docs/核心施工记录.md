## 2026-08-31 · A22 会话持久化（T2）

**做了什么**：把 refresh token 从 kvstore（Redis/内存）迁移到持久化的 `user_sessions` 表。

**为什么**：原实现 refresh token 只存 kvstore——云端存 Redis、桌面本地模式存内存 kv。桌面端重启即掉登录，「3 端在线 + 踢最早」无落点，设备管理页无法列出设备（方案 v3 缺口 K5）。

**实现了什么**：
1. 新增 `user_sessions` 表（model/repo/repository 三件套），字段含 jti（唯一）、设备名/类型/IP、last_active_at、expires_at。
2. `issueTokens` 改写：签发时落一条 session 行（滑动 30 天窗口 = refresh TTL），并强制「单账号最多 3 会话」，超出踢最早活跃。
3. `Refresh` 改写：按 jti 原子消费旧 session（单条 DELETE，RowsAffected 判重，杜绝并发双刷），携带旧设备元数据签发新 session（避免刷新被误判成新设备撞 3 端上限）。
4. `Logout` 改写：单会话吊销走 `Consume(jti)`，全量下线走 `DeleteByUser`。
5. 新增 `GET /api/v1/auth/sessions`、`DELETE /api/v1/auth/sessions/:id` 设备管理端点；设备类型由 User-Agent 识别（Electron→桌面、mobile 关键词→移动、其余→web）。
6. 短信验证码仍走 kvstore（无需设备维度），不受影响。

**取舍**：保留 kvstore 仅用于短信验证码与限流；refresh 会话全量迁表。local 模式 SQLite 持久化，云端 PG 持久化，双模式行为一致。设备管理前端 UI 暂缓，后端端点已就绪。

**验收**：`go build ./... && go vet ./... && go test ./...` 全绿。

## 2026-08-31 · A23 阅读数据回流 + 追更计数修复

**做了什么**：① 作者侧新增阅读数据端点与面板；② 修复追更计数膨胀 bug。

**为什么**：飞轮「创作→发布→阅读→互动→反哺」缺最后一段——作者发布了作品却看不到任何读者数据（方案 v3 判断三：没有反馈闭环）。同时 `Follow` 无条件 `IncFollowCount`，重复点追更会让计数虚高。

**实现了什么**：
1. 新增 `GET /api/v1/publish/works/:wid/stats`，返回追更人数、累计阅读人数、每章当前阅读人数漏斗。
2. 仓储层新增 `ReadingDistribution`（按 chapter 聚合最新进度）与 `DistinctReaders`（COUNT DISTINCT user_id）。
3. 前端 `WorkStatsPanel` 组件 + 接入发布弹窗（PublishModal），展示追更/阅读指标卡与每章阅读漏斗条。
4. `Follow`/`Unfollow` 改为幂等：已关注则不重复计数、未关注则不重复扣减；`UpsertFollow` 冲突更新不再覆盖 `created_at`（原实现会把关注时间重置为零值）。

**取舍**：reading_progress 只存读者「最后位置」，每章人数 = 读者最后停留点，是对读完率的诚实近似；要精确到「每章完成率」需另加逐章进度事件表（列入后续 E5 埋点），本期不引入。

**验收**：`go build ./...`、`pnpm build` 全绿。
