## 2026-08-31 · A22 会话持久化（T2）

**做了什么**：把 refresh token 从 kvstore（Redis/内存）迁移到持久化的 `user_sessions` 表。

**为什么**：原实现 refresh token 只存 kvstore——云端存 Redis、桌面本地模式存内存 kv。桌面端重启即掉登录，「3 端在线 + 踢最早」无落点，设备管理页无法列出设备（方案 v3 缺口 K5）。

**实现了什么**：
1. 新增 `user_sessions` 表（model/repo/repository 三件套），字段含 jti（唯一）、设备名/类型/IP、last_active_at、expires_at。
2. `issueTokens` 改写：签发时落一条 session 行（滑动 30 天窗口 = refresh TTL），并强制「单账号最多 3 会话」，超出踢最早活跃。
3. `Refresh` 改写：按 jti 原子消费旧 session（单条 DELETE，RowsAffected 判重，杜绝并发双刷），携带旧设备元数据签发新 session（避免刷新被误判成新设备撞 3 端上限）。
4. `Logout` 改写：单会话吊销走 `Consume(jti)`，全量下线走 `DeleteByUser`。
5. 新增 `GET /api/v1/auth/sessions`、`DELETE /api/v1/auth/sessions/:id` 设备管理端点；设备类型由 User-Agent 识别（Electron→桌面、mobile 关键词→移动、其余→web）。
6. 短信验证码仍走 kvstore（无需设备维度），不受影响。

**取舍**：保留 kvstore 仅用于短信验证码与限流；refresh 会话全量迁表。local 模式 SQLite 持久化，云端 PG 持久化，双模式行为一致。设备管理前端 UI 暂缓，后端端点已就绪。

**验收**：`go build ./... && go vet ./... && go test ./...` 全绿。

## 2026-08-31 · A23 阅读数据回流 + 追更计数修复

**做了什么**：① 作者侧新增阅读数据端点与面板；② 修复追更计数膨胀 bug。

**为什么**：飞轮「创作→发布→阅读→互动→反哺」缺最后一段——作者发布了作品却看不到任何读者数据（方案 v3 判断三：没有反馈闭环）。同时 `Follow` 无条件 `IncFollowCount`，重复点追更会让计数虚高。

**实现了什么**：

2. 仓储层新增 `ReadingDistribution`（按 chapter 聚合最新进度）与 `DistinctReaders`（COUNT DISTINCT user_id）。
3. 前端 `WorkStatsPanel` 组件 + 接入发布弹窗（PublishModal），展示追更/阅读指标卡与每章阅读漏斗条。
4. `Follow`/`Unfollow` 改为幂等：已关注则不重复计数、未关注则不重复扣减；`UpsertFollow` 冲突更新不再覆盖 `created_at`（原实现会把关注时间重置为零值）。

## 2026-09-03 · AI 起稿滑动切换器：倒退切换失败修复 + 阶段快照预览/采纳

**做了什么**：修复滑动选择器倒退切换报「切换阶段失败」，并补齐「按阶段存储结果 + 切换回看预览 + 底部阶段采纳」能力（接上此前被中断的一轮施工）。

**为什么**：节点标签 `<button onClick={jumpStage}>` 与轨道 `onPointerUp={handleDragEnd}` 都会触发 `jumpStage`，单次点按/拖动 = 两次 `POST /story/jobs/:id/stage`；该端点挂在 AI 限流组（`http.go:482` `RateLimiter.Scope(middleware.ScopeAI)`，`http.go:513` 注册），第二次请求被 429 拒绝 → 前端 toast「切换阶段失败」。倒退/前进都中招，倒退更常被快速点按触发。原实现也无历史阶段回看手段（预览只读当前 `stage_payload`）。

**实现了什么**：
1. 前端去重：节点标签改为非交互 `<div>`，点击/拖动统一由轨道 pointer 事件处理（pointerdown 设 `dragStageIdx`、pointerup → `handleDragEnd` 单次 `jumpStage`），消除重复提交。
2. 后端按阶段存结果：`StoryJob` 新增 `StageSnapshots jsonb`；`GenerateStage`/`runVerifyStage` 把本阶段纯净结果写入 `stage_snapshots[stage]`（保留 `stage_payload` 存当前生成 + 采纳记录）；`toResponse` 回传 `stage_snapshots`（DTO `StoryJobResponse` 与前端 `StoryJob.stage_snapshots` 均已接）。
3. 前端切换预览：`StagePreview` 改为读 `stage_snapshots[job.stage] ?? stage_payload`，切换回历史阶段即展示当时生成结果；重新点「生成当前阶段」会覆盖该阶段快照（重做替换）。
4. 底部阶段采纳：`StagePreview` 底部新增按阶段采纳——成稿阶段「采纳到章节」（落库真实章节），其余有结果的阶段「采纳本阶段并进入下一阶段」（确认并推进）。

**取舍**：非成稿阶段的「采纳」语义等价于 `AdvanceStage`（确认结果并进入下一阶段），因大纲/分章等产物仅预览态、无独立落库端点；成稿才有 adopt→chapters 落库。`verify` 阶段为一致性报告、无采纳按钮。

**验收**：`go build ./...`（server，exit0）、`pnpm exec tsc --noEmit`（web，exit0）全绿；`/stage` 限流根因已定位并消除重复提交。

## 2026-08-31 · 修复：发布弹窗内容被遮挡（fixed 弹窗被困 containing block）

**现象**：文章发布窗口（PublishModal）打开后内容被遮挡/错位。

**根因**：代码库存在两套弹窗写法——`common/Modal.tsx`（portal 到 body，正确）与手写 `fixed inset-0` 弹窗（错误）。手写弹窗只要挂在带 `backdrop-filter`/`transform`/`filter` 的祖先节点下，该祖先就会成为 fixed 后代的 containing block，`inset-0` 不再覆盖视口，弹窗被压缩进祖先盒子里、内容被编辑器其它表面遮挡。PublishModal 恰好挂在 Toolbar 内，而 Toolbar 根节点带 `backdrop-blur`；`glass-panel`（common Modal 面板）同样带 `backdrop-filter: blur(16px)`，会殃及嵌套其中的手写 fixed 层（版本对比 DiffViewer）。

**修复**（全部改为 portal 到 `document.body`，与 common/Modal 策略一致）：
1. `PublishModal` —— 根节点包 `createPortal(document.body)`。
2. `DiffViewer` —— 根节点 portal（同时修复编辑器内与版本对比弹窗内两种使用场景）。
3. `VersionCompare` 加载遮罩 —— portal。

**为什么“总是”出这类问题**：手写 fixed 弹窗没有强制 portal 的约定，只要有人在带 backdrop-filter/transform 的容器里再挂一个手写弹窗就会复发。已在此三处注释中写明原因；后续新增弹窗应一律走 `common/Modal` 或自行 portal。

**验收**：`pnpm build` 全绿。

## 2026-08-31 · Docker 镜像构建链路修复（dev 全栈 can't start）

**问题**：用户执行 `docker compose up -d` 失败，报 `corepack prepare pnpm@latest --activate` 网络错误，build web 镜像失败。

**根因（三处，逐一修复）**：
1. **corepack 网络解析**：`packages/web/Dockerfile`（含 `Dockerfile.dev`）用 `corepack prepare pnpm@latest`，需在容器内实时拉取 npmjs.org 解析 `@latest`，在受限网络下必失败。修复：改为**固定 pnpm 版本** `pnpm@11.13.0`（与本机一致），并新增 `ARG NPM_REGISTRY` 默认指向 `registry.npmmirror.com`，经 `npm_config_registry`/`COREPACK_NPM_REGISTRY` 注入，海外可在 build 时用 `--build-arg` 覆盖官方源。
2. **Node 版本过旧**：web 基础镜像 `node:20-alpine` 运行 pnpm@11 会报 `ERR_UNKNOWN_BUILTIN_MODULE`（pnpm 11 需 Node22+）。修复：升到 `node:22-alpine`。
3. **node_modules 被宿主覆盖**：web build context 为仓库根，`COPY packages/web/ packages/web/` 会把宿主 Windows 版 `node_modules` 拷进 Linux 容器，覆盖 pnpm 生成的符号链接，导致 `tsc` 无法解析。修复：新增根 `.dockerignore` 排除 `node_modules`、`.git`、`.env`、`packages/desktop` 等。

**连带修复（服务器/AI 镜像同类问题）**：
1. **Go 版本不匹配**：`packages/server/Dockerfile` 用 `golang:1.22-alpine`，但 `go.mod` 要求 `go >= 1.26.5`，`go mod download` 直接失败。修复：升到 `golang:1.26-alpine`。
2. **GOPROXY**：新增 `ARG GOPROXY` 默认 `goproxy.cn,direct`，解决模块下载受限。
3. **PIP 源**：`packages/ai-service/Dockerfile` 新增 `ARG PIP_INDEX` 默认清华镜像 `pypi.tuna.tsinghua.edu.cn/simple`，解决 pip 安装受限。

**取舍**：依赖源默认走中国镜像以贴合本机/国内网络，但全部做成 `ARG` 可覆盖，保证 CI/海外部署不变；`.dockerignore` 放在仓库根（web build context），server/ai 各自 context 不受影响。

**验收**：`docker build` 三镜像（web/server/ai-service）各自成功：web `naming to inkbloom-web:test done`、server `naming to inkbloom-server:test done`、ai `naming to inkbloom-ai:test done`。

**取舍与理由**：

## 2026-09-03 · WS /ws ECONNRESET 修复（cloud 模式根因）

**根因**：dev 服务跑 cloud 模式（`run_mode=cloud`），`IsLocal()` 为 false；`CORSOrigins` 仅来自环境变量 `INKBLOOM_SERVER_CORS_ORIGINS`，未配置则为空 → WS 白名单恒空 → vite（localhost:3000）握手被 403 → `read ECONNRESET`。此前 gated 在 `IsLocal()` 的修复因此失效。

**修复**：`cors.go` 导出 `DefaultDevOrigins`（含 localhost:5173/3000、127.0.0.1:5173/3000、127.0.0.1:18080）；`main.go` 改为 `CORSOrigins` 为空时回退 `middleware.DefaultDevOrigins`，与 CORS 中间件同契约（cloud-dev 与 local-dev 均生效）。`websocket.go` 的 `originAllowed` 白名单因此放行 dev 源 → 101。

**取舍**：不依赖 `IsLocal()`，改为「配置为空→dev 默认源」的统一回退，避免环境差异再次漏配。

**验收**：`go build ./internal/middleware/` 与 `go build ./cmd/server/` 均 exit 0。本地 `INKBLOOM_MODE=local` 起服务后，对 `/ws` 做浏览器式握手探活（带 `Origin` + `Connection: Upgrade` + `Sec-WebSocket-Version:13` + `Sec-WebSocket-Key` 头），结果：
- `Origin: http://localhost:3000`（vite dev）→ **HTTP 101 升级成功** ✅
- `Origin: http://127.0.0.1:3000` → **101** ✅
- `Origin: http://127.0.0.1:18080`（桌面内嵌 shell）→ **101** ✅
- `Origin: http://evil.example.com`（负向）→ **403**，`websocket.go:199` 记 `WebSocket origin rejected` ✅
- 无 `Origin`（curl / 桌面 loopback 页）→ **101** ✅

即 dev 源握手成功升级、非法源被拒，根因闭环。坑（已排）：Go-on-Windows 把 `-o /tmp/x` 写成 `C:\tmp\x`，而 bash 的 `/tmp` 解析为 msys 临时目录（`$TEMP`＝`C:\Users\...\AppData\Local\Temp`），二者不一致——此前 `ws_verify.sh` 实际跑的是旧二进制（`C:\Users\...\Temp\inkbloom-server`，Sep 1）导致误报 403；改 `go build -o "$TEMP/inkbloom-server"` 后探活才是新二进制。
