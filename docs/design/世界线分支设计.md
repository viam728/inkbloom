# 世界线分支设计书（施工 Prompt）

> 需求出处：`docs/备忘录.md` L23「考虑世界线分支怎么做」。
> 本文是自包含施工提示词：实现者只需读本文件 + 文中引用的代码位置，不需要重新推导设计意图。
> 交付形态：服务端（Go/GORM/PostgreSQL+SQLite 双方言）+ 创作端 Web（React/zustand）+ 读者端（/read 路由）三端贯通。

---

## 0. 一句话定位

**一本书就是一个仓库，一条世界线就是一个 git 分支**：大纲章节节点是锚点，每条世界线在"锚点 × 世界线"粒度上持有两份档案——编辑版本档案（chapter_versions 快照链 + 指针）与发布版本档案（published_chapters 冻结副本）；**切换分支 = 切换世界线**，创作端 checkout 物化工作副本，读者端按线读取已发布链。

### 0.1 术语对照（git ↔ 世界线）

| git 概念 | 世界线体系 | 落点 |
|---------|-----------|------|
| repository | 一本书（novel） | `novels` |
| blob/commit | 章节内容快照（不可变，带 worldline_id 标记） | `chapter_versions` |
| branch | 世界线 | `worldlines`（新表） |
| branch tip（每文件一个 ref） | 每节点编辑指针 | `worldline_node_states.edit_version_id`（新表） |
| working tree | 章节工作副本（永远是激活线的物化） | `chapters` |
| checkout | 切换世界线（flush 快照 + 物化入线内容） | `POST /worldlines/:wid/checkout` |
| fork | 从锚点节点分叉（只复制指针，零内容拷贝） | `POST /novels/:id/worldlines` |
| push / 发布 | 该线发布链（冻结副本 + 发布里程碑） | `published_chapters(worldline_id)` |
| merge | v2 预留（cherry-pick 单节点内容采纳） | 不在本文范围 |

## 1. 需求拆解与核心决策

### 1.1 用户需求原话拆解

1. 「类似于 git 分支那样」→ 分支隔离、切换、分叉；分支间内容互不污染。
2. 「利用大纲章节节点来作为锚点」→ 分叉/比较/发布的原子单位是**大纲节点**（`OutlineNode.id`，`crypto.randomUUID()` 字符串），不是章节表主键。
3. 「每一条分支选中一条节点链」→ 世界线 = 大纲全序节点链上的**指针集合**；v1 所有线共享同一大纲结构（同一份 acts JSON），分叉差异在"节点背后的文本"，不在"节点成员资格"（v2 预留成员差异，见 §4.6）。
4. 「节点背后是编辑版本和发布版本两个文章存档」→ 双档案：
   - **编辑档案**：`chapter_versions` 快照链（auto/milestone/ai_rewrite/rollback），每线独立成链，指针在 `worldline_node_states`；
   - **发布档案**：`published_chapters` 冻结副本，按 `(work_id, worldline_id, chapter_id)` 一线一份。
5. 「切换分支就是切换世界线」→ 创作端任意时刻只物化**一条激活世界线**的工作副本（novel 级 active 指针）。
6. 「创作与读者双端打通」→ 读者端可浏览/切换已发布的世界线，阅读进度按线隔离；创作端发布时明确"发到哪条线"。

### 1.2 核心决策：指针模型 + checkout 物化（而非复制章节实体）

**结论**：章节实体（`chapters` 行）全局共享、每线只持"版本指针"；切换世界线时把入线指针指向的快照内容物化进工作副本。

对比过的备选方案：

| 方案 | 做法 | 否决/采纳理由 |
|------|------|--------------|
| B. 复制章节实体 | fork 时对锚点之后的节点各建新 `chapters` 行 | 否决。`chapter_id` 是全系统 join 键（media、foreshadow、knowledge、interaction、published、task、agent 上下文），复制造成实体扇出迁移，且 fork 即拷贝正文违背「最小 tokens/零拷贝」原则 |
| A′. 不物化，读时按线解析 | 编辑器按 `(worldline, node)` 现查档案 | 否决。所有直读 `chapters.content` 的路径（AI 上下文、字数统计、同步、发布）都要显式穿线，漏一处即脏读 |
| **A. 指针 + 物化（采纳）** | 工作副本恒等于激活线；切换 = flush + 物化 | **采纳**。git 语义最忠实；既有"读工作副本"的全部链路零改造；切换是一个显式事务，一致性好验证 |

**采纳 A 的关键前提**（现有机制恰好满足）：
- 快照去重按 content hash（`chapter_version_repo.go` 的连续同 hash 跳过）→ 物化产生的重复快照可被"按线判重"天然吸收（§4.5 需升级判重维度）；
- `HistoryService.CreateSnapshot` 已是统一快照入口（`history_service.go`）→ 打线标只需过这里。

## 3. 数据模型

### 3.1 新表一：`worldlines`（世界线注册表）

```sql
-- packages/server/migrations/027_worldlines.up.sql
CREATE TABLE IF NOT EXISTS worldlines (
    id            BIGSERIAL PRIMARY KEY,
    user_id       BIGINT NOT NULL,
    novel_id      BIGINT NOT NULL,
    name          VARCHAR(50) NOT NULL,          -- 线内唯一，如「主线」「复仇线」
    description   TEXT NOT NULL DEFAULT '',
    source        VARCHAR(16) NOT NULL DEFAULT 'user',   -- 'user' | 'ai'
    is_mainline   BOOLEAN NOT NULL DEFAULT FALSE,        -- 每书恰一条，不可删不可归档
    -- 分叉信息；主线两列均为 NULL
    fork_node_id  VARCHAR(64),                   -- 锚点：大纲节点 id（OutlineNode.id）
    fork_from_worldline_id BIGINT,               -- 父线
    status        VARCHAR(16) NOT NULL DEFAULT 'active', -- 'active' | 'archived'
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_worldlines_novel_name ON worldlines(novel_id, name);
CREATE INDEX IF NOT EXISTS idx_worldlines_novel ON worldlines(novel_id);
```

- 归档（`status='archived'`）代替硬删除：快照是不可变历史，硬删除会留下悬空指针。v1 不提供硬删除。
- 主线规则：迁移回填时每本书生成一条 `is_mainline=true, name='主线'`；主线不可 fork 自他线、不可归档、不可改名删除。

### 3.2 新表二：`worldline_node_states`（节点链指针表，本设计的核心）

```sql
CREATE TABLE IF NOT EXISTS worldline_node_states (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT NOT NULL,
    novel_id        BIGINT NOT NULL,
    worldline_id    BIGINT NOT NULL,
    node_id         VARCHAR(64) NOT NULL,        -- OutlineNode.id（UUID 字符串）
    chapter_id      BIGINT NOT NULL,             -- 该线该节点绑定的成稿章节（seed 时从大纲捕获）
    edit_version_id BIGINT,                      -- 编辑档案指针 → chapter_versions.id；NULL=尚未成稿
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_wlstate_line_node ON worldline_node_states(worldline_id, node_id);
CREATE INDEX IF NOT EXISTS idx_wlstate_chapter ON worldline_node_states(chapter_id);
```

- 「每一条分支选中一条节点链」的落点：**一条线的 state 行全集（按大纲序排列）就是它的节点链**。
- `edit_version_id` 指向的快照必须满足 `chapter_versions.chapter_id = state.chapter_id AND worldline_id = state.worldline_id`（服务端写入时保证）。
- **发布档案不在此表**：发布状态单一来源是 `published_chapters(worldline_id)`，避免双写漂移。
- 大纲节点被删除 → 级联删所有线的对应 state 行（§4.6）；大纲节点被重绑到别的章节 → 重 seed（§4.6）。

### 3.4 回填（迁移内或启动时幂等执行）

1. 对每本书：`INSERT worldlines (novel_id, name, is_mainline) SELECT … ON CONFLICT DO NOTHING`（name='主线'）。
2. `UPDATE chapter_versions/published_chapters SET worldline_id = 主线id WHERE worldline_id = 0`。
3. `UPDATE reading_progress SET worldline_id = 主线id WHERE worldline_id = 0`。
4. 已有历史行为零变化：回填后所有旧快照/旧发布副本全部归属主线，读者端不传 `?line=` 时默认读主线，现网体验不变。

## 4. 核心语义规则（七条铁律）

### 4.1 编辑：工作副本恒等于激活线

保存章节（现有 `chapter_service` 保存路径）→ `HistoryService.CreateSnapshot` 打 auto/ai_rewrite/rollback 快照时**盖章 `worldline_id = novels.active_worldline_id`** → 服务端同步 `UpsertState(激活线, node_id, edit_version_id = 新快照 id)`。node_id 由"章节 → 绑定它的大纲节点"反查（`outlineChapterOrder` 同源逻辑在服务端已有对应实现，复用 outline 同步的映射；反查不到的游离章节只盖章不打指针）。

### 4.2 切换世界线（checkout）——一个事务，三步

`POST /api/v1/novels/:id/worldlines/:wid/checkout`：

1. **Flush（防丢）**：对出线（当前 active）下"工作副本 ≠ 指针快照"的节点补 auto 快照（盖章出线）。判定：`sha256(chapters.content)[:16] ≠ state.edit_version_id 快照的 content_hash` 即补。未保存的编辑器内容由前端在调用前先走常规保存（服务端兜底仍保留此步）。
2. **Materialize（物化）**：遍历入线的 state 行——`edit_version_id != NULL` 的节点，把该快照的 `title/content/content_json/word_count` 写回 `chapters` 行；`edit_version_id IS NULL`（未成稿节点）把工作副本清为空文本。**不新建任何快照**（靠 §4.5 按线判重吸收后续 auto 噪声）。
3. **切指针**：`novels.active_worldline_id = wid`，返回 `{ worldline, chain }`。

- 前置守卫：`task_engine` 有该书运行中任务 → 409（Agent 改写中途切换会造成半成品文本落错线）。
- 前端收到成功响应后强制 reload 章节列表 + 编辑器内容 + 大纲徽章（多标签页一致性以服务端 last-write-wins，切换动作本身要求显式确认弹窗，见 §6.2）。

### 4.3 分叉（fork）——只复制指针，零内容拷贝

`POST /api/v1/novels/:id/worldlines`，body：`{ name, description?, fork_node_id, fork_from_worldline_id?, source? }`：

1. 校验：锚点节点存在于当前大纲 acts 且已绑成稿章节（`chapter_id != null`）；`fork_from_worldline_id` 缺省取当前激活线；name 线内唯一（≤50 字符）。
2. **Seed**：对大纲**全部**已绑章节节点（不只锚点之后——这是与直觉方案的关键差异，理由见 §1.2 方案 A 的"分支拥有全树"语义）插入 state 行：
   - 父线该节点 `edit_version_id != NULL` → 直接复制其指针；
   - 父线指针为 NULL 但章节工作副本非空（旧数据未建链）→ 先补 auto 快照（盖章父线）再指；
   - 未成稿节点 → `edit_version_id = NULL`。
3. 新线不自动激活（留在原线继续写是常态）；返回新线 + chain。

效果：新线与父线在分叉瞬间**内容完全一致**；此后任何一线上对任何节点的编辑都只移动自己的指针，互不可见——包括锚点之前的节点（git 里分支拥有全部文件的历史，"共享前缀"只是历史同源，不是共享可变状态）。差异视图（§6.4）会展示"两线实际分叉在第几个节点"（首个指针内容 hash 不同的节点）。

### 4.4 发布：发布档案按线归档

`PublishChapter`（`publish_service.go:180`）改造，发布目标 = **当前激活线**：

1. 安全检查、HTML 清洗：原样不动。
2. 发布 milestone 清理：`DeletePublishMilestones` 改为按 `(chapter_id, worldline_id)` 清理，label 格式从 `发布《书名》第N章` 扩为 `发布《书名》·线名·第N章`（历史面板可读）。
3. milestone 快照盖章 `worldline_id = 激活线`。
4. `UpsertChapter` 去重键扩为 `(work_id, worldline_id, chapter_id)`：同线重发覆盖该线读者快照；**他线副本不受影响**——这是双端打通的根基：不同读者可以在不同线上同时各读各的。
5. `Position` 语义不变（大纲序 rank）；v1 所有线共享大纲结构，故目录序天然一致。

「整线发布」批量端点（W3）：对激活线上所有 `edit_version_id != NULL` 且未发布/有改动的节点循环走单章发布，返回逐章结果。

### 4.5 自动快照判重升级：全局 hash 判重 → `(chapter_id, worldline_id)` 判重

现状：连续 auto 快照同 hash 跳过（chapter 粒度）。物化切换后，若不按线判重，A 线的 hash 会让 B 线物化后的首个 auto 快照被误跳，导致 B 线缺自己的基线快照。**实现**：判重查询改为"该章节在**当前写入线**上的最近一条快照 hash 相同则跳过"。这是 checkout 正确性的隐形支柱，W1 必须与迁移同批完成。

### 4.6 大纲结构变更（结构全局共享的代价与处理）

- **增节点**（`outline-store.addNode` / Agent 改大纲）：大纲保存链路（`novel_doc_service`/outline 保存端点）在持久化 acts 成功后，为新节点做章节绑定（现状已如此）；绑定成功后为**所有** status='active' 的线 seed `edit_version_id=NULL` 的 state 行（新节点 born empty，各线独立书写）。
- **删节点**：级联 `DeleteStatesByNode`（所有线）。其历史快照不删（不可变档案，保留任务管生命周期）。
- **重绑章节**（node.chapter_id 变更）：删该节点所有线 state 行，按 §4.1 语义在下一次保存时自然重建（旧快照留在旧章节名下，不影响）。
- **成员差异预留（v2）**：state 行的缺席未来可解释为"该线不含此节点"；v1 恒为全集，UI 不暴露成员编辑。

### 4.7 保留任务（retention sweep）不得删被引用快照

`PruneAuto`/`PruneAutoBefore`/`SweepExpiredVersions` 增加排除条件：快照 id 被 `worldline_node_states.edit_version_id` 或 `published_chapters.version_id` 引用的一律跳过（NOT IN / NOT EXISTS 子查询，方言可移植——参考 `published_repo.go` SyncPositionsFromChapters 的写法）。违反此条的后果是指针悬空、checkout 物化到空文本，属最高优先级数据事故。

## 5. API 契约

统一前缀 `/api/v1`，所有权隔离沿用 `scope.ForUser` + `user_guard`。

### 5.1 世界线管理（创作端）

| 方法 | 路径 | 语义 |
|------|------|------|
| GET | `/novels/:id/worldlines` | 列表（含主线）。每项：`{ id, name, description, source, is_mainline, status, fork_node_id, fork_node_title, fork_chapter_position, fork_from_worldline_id, chapter_count(有成稿指针数), published_count, word_count(按指针快照汇总), last_edited_at, is_active }` |
| POST | `/novels/:id/worldlines` | 分叉。body `{ name, description?, fork_node_id, fork_from_worldline_id?, source? }`；409=Agent 任务运行中；422=锚点无效/重名 |
| PATCH | `/worldlines/:wid` | 改 `name/description`；主线禁改名 |
| POST | `/worldlines/:wid/archive` | 归档（软删）。主线 405；若有该线未发布草稿差异，响应带 `warning` 供前端二次确认 |
| GET | `/novels/:id/worldlines/:wid/chain` | 节点链视图：`[{ node_id, act_id, act_title, node_title, chapter_id, edit_version_id, word_count, published: { work_id, published_at } \| null, differs_from_parent: bool }]`（按大纲序） |
| POST | `/novels/:id/worldlines/:wid/checkout` | §4.2。响应 `{ worldline, chain, materialized_chapters: n }` |

### 5.2 发布（创作端，扩展现有端点）

- `POST /publish/works/:workId/chapters`：**不改入参**，服务端以 `novels.active_worldline_id` 为发布线（作者永远在"当前线"上操作，心智一致）。响应 `PublishedChapterResponse` 增加 `worldline_id`。
- `GET /publish/works/:workId/chapters`：响应按线分组或带 `worldline_id`（取当前激活线过滤 + `?all_lines=1` 全量，供发布面板"各线发布状态"列表）。
- `GET /publish/works/:workId/lines`：读者侧可见的线清单（创作端预览用）：`[{ worldline_id, name, chapter_count, last_published_at }]`。

### 5.3 阅读端（匿名可读部分沿用现有公开路由风格）

| 方法 | 路径 | 语义 |
|------|------|------|
| GET | `/read/works/:slug` | work 详情新增 `lines: [{ id, name, description, chapter_count, fork_point_label("自第N章分叉"), is_default, updated_at }]`（只含已发布≥1章的线；主线恒在首位） |
| GET | `/read/works/:slug/chapters?line=:wid` | 指定线目录；缺省=主线 |
| GET | `/read/chapters/:pid` | pid 本身已绑定具体发布副本（按线独立），**无需改**——交互（评论/情绪）挂在 pid 上天然按线隔离 |
| GET/PUT | `/read/progress?work_id=&line=` | 进度按线；缺省=主线（老读者链接完全兼容） |

follow 保持 per work（关注的是书不是线）；更新通知在 payload 里带"哪条线更新了"。

### 5.4 DTO 与错误码

- 新增 `dto/worldline_dto.go`：`WorldlineResponse`、`WorldlineChainItem`、`CreateWorldlineRequest`、`CheckoutResponse`。
- 错误：`ErrWorldlineNameTaken`、`ErrMainlineImmutable`、`ErrCheckoutBlocked`（Agent 忙）、`ErrForkAnchorInvalid`。HTTP 映射沿用现有 `handler` 错误翻译模式。

## 7. 读者端设计

### 7.1 信息架构

- work 详情页（`/read/:slug`）：若 `lines.length > 1`，标题下渲染**世界线选择带**——横排 pill：`主线`《复仇线》`（+N）`；选中态高亮；每条 pill 副标 `自第12章分叉 · 8章`。
- 目录页与章节阅读页 URL 均携带线：`/read/:slug?line=:wid`（query 而非 path 段——主线默认无参数，老链接零迁移）。
- 章节页顶栏同款选择器；切换线 = 跳转到该线目录（不试图对齐进度——两线章节内容本就不同）。
- 阅读进度按线恢复（`reading_progress(user, work, line)`）；"继续阅读"按钮取当前 URL 线的进度。

### 7.2 读者感知约束（刻意设计）

- 读者**只能读已发布的线**，且看不到"该线与主线相同的前缀章节"的任何实现细节——对读者它就是一本完整的书。
- 线描述（`description`）是作者写给读者看的"这条线有什么不同"（如"如果主角当年没有离开小镇"），发布整线时提示作者填写。
- 发现页卡片：`lines_count > 1` 时显示 `N 条世界线` 角标；排序权重 v1 仍按主线（多线不计入热度，防止刷线）。

## 9. 迁移与兼容

1. **迁移 027**（`migrations/027_worldlines.up.sql` + `.down.sql`）：§3.1–3.3 DDL + §3.4 回填。down：drop 新表、drop 新列（reading_progress 旧唯一索引还原）。
2. **桌面端（SQLite）**：模型加字段走 AutoMigrate（契约 C1，与 `OutlineVersion` 同策略）；主线回填逻辑放服务启动迁移钩子（幂等：`SELECT` 无主线的书才插），云端/本地共用同一段 Go 回填代码，SQL 迁移里只做 DDL。
3. **兼容红线**：
   - 旧读者链接（无 `?line=`）行为不变（=主线）；
   - 不创建任何世界线（从不点开该功能）的作者：全部行为与现状逐字节一致（state 表只会在 fork 时 seed，主线编辑是否回写主线 state 行采用**懒建**——主线指针仅在用户显式使用线功能后才 seed，避免全量书籍写放大）；
   - `DeletePublishMilestones` 新旧逻辑以 `worldline_id` 是否存在区分（0=旧格式全清）。

## 10. 边界与风控

| 风险 | 对策 |
|------|------|
| 切换时未保存内容丢失 | 前端保存前置 + 服务端 flush 兜底（§4.2 步骤 1） |
| Agent 任务运行中切换/分叉 | task_engine 活跃任务检查 → 409 |
| 指针悬空（快照被清理/删除） | §4.7 保留任务排除 + 读取时防御：指针快照缺失 → 回退"该章该线最近快照"并 WARN 日志 |
| 大纲节点 id 失稳（UUID 理论上不变，但导入合并可能重生成） | chain 视图渲染时过滤孤儿 state 行 + WARN；不做自动重挂 |
| 多标签页并发编辑不同线 | 服务端 last-write-wins + 切换广播事件；文档标注"单人单编辑会话"假设 |
| 线爆炸（无上限 fork） | 每书上线数上限 20（422 提示先归档）；发现页不计多线热度 |
| 中文线名 | name 仅查重与展示，不做 slug 化 |

## 12. 总验收清单（用户视角的一句话检验）

1. 作者在《书》第 12 章"如果当初……"处一键分叉出《如果线》，写下与主线不同的第 12–20 章，主线一个字没变。

4. 从不使用该功能的作者：零感知，零迁移成本，旧数据原样。
