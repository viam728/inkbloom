# 世界线创作设计书（树创作画布 · 施工 Prompt）

> 需求出处：世界线创作的树形体验——结合节点编辑/思维导图的工作方式，基于《世界线分支设计》（`docs/design/世界线分支设计.md`，下称《分支设计》）与大纲节点体系，提供 Xmind 式的全屏树创作面板，深度结合 Agent 生成。
> 本文是自包含施工提示词：实现者只需读本文件 + 文中引用的代码位置；与《分支设计》冲突处以本文为准（本文只做增量，不改其数据模型）。

---

## 0. 一句话定位

**世界线创作画布**：一个从世界线入口进入的全屏思维导图面板——根节点是"书 × 当前世界线"，一级分支是幕（act），链上是章节节点（outline node）；每个节点既能手写也能让 AI 写下一个节点，也能从任一节点让 AI 一次生成一条脉络（N 个节点的情节推进）；**节点没写完（标题+简介齐备）就不许长出下一个**。

### 0.1 与《分支设计》的分工

| 概念 | 归属 | 在画布中的角色 |
|------|------|---------------|
| 世界线（worldlines / checkout / fork） | 《分支设计》 | 画布顶栏切换器决定"我在哪条线上规划"；节点菜单「从此分叉世界线」调《分支设计》§4.3 的 fork API |
| 节点双档案（编辑/发布版本） | 《分支设计》 | 画布节点徽章只读展示（成稿态/发布态/与父线差异），不提供档案操作 |
| 大纲结构（acts JSON） | 本文 | 画布是大纲结构的**第二个编辑器**（与 OutlinePanel 并列，同一份数据、同一保存链路） |
| 脉络候选（veins） | 本文（新增） | 挂在节点上的候选支线，纯大纲 JSON 扩展键，零新表 |

## 3. 数据模型（零新表）

### 3.1 结论

画布**不新增任何表**。全部状态落两处：① 既有的 `novel_outline.acts` JSONB（大纲链 + 脉络候选）；② 既有 `worldlines`/`worldline_node_states`（《分支设计》，只读展示 + fork 调用）。前端新增 `canvas-store`（视口、选中、折叠、预览态等纯 UI 状态，不持久化到服务端，localStorage 存视口即可）。

### 3.2 acts JSON 增量键（normalize 未知键透传，向后兼容）

```ts
/** 大纲节点新增可选键（服务端 opaque，仅画布与校验感知） */
interface OutlineNode {
  // …既有字段不变…
  /** AI 生成标记：'ai' = AI 创建；手工创建不写。徽章与统计用 */
  gen?: 'ai';
  /** 同一批脉络生成的批次 id（UUID）。用于「整批重生成/整批删除」 */
  vein_id?: string;
  /** 挂在此节点下的候选支线（脉络候选）：不入主链、不参与门禁、不绑章节 */
  veins?: VeinCandidate[];
}
interface VeinCandidate {
  id: string;            // crypto.randomUUID()
  title: string;
  summary: string;
  gen?: 'ai';
  created_at: string;
}
```

- `outline_normalize.go` 已按未知键透传契约工作（`novel_outline.go` 注释明确 acts 由前端持有），**无需改 Go 校验**；仅 §6.2 的门禁校验新增。
- `veins[]` 与主链节点同构但轻量：无 status/chapter_id/memory_refs——候选不占成稿状态机。

### 3.3 与 novel_branches（世界树）的关系

不合并、不迁移。`novel_branches` 继续承载 Agent 在对话里用 `save_branch` 沉淀的分歧图（WorldTreePanel 展示）；画布的 `veins[]` 承载作者在规划时"从某节点岔出去看看"的候选支线。二者都可通过各自入口「落地/提升」进主链或世界线（§5.4）。

## 5. 节点交互设计

### 5.1 节点解剖（`CanvasNode`）

- **标题行**：`OutlineNode.title`，单击进入就地编辑（受控 input，Enter 提交 / Esc 还原）。
- **简介区**：折叠态显示 `stripTags(summary)` 前 60 字；展开态就地编辑——**纯文本 textarea**，提交时用共享的 `toEditorHtml` 包裹为 HTML（OutlineNodeEditor 已迁移 summary 为 HTML，画布必须写同构数据；助手抽为 `web/src/utils/outline-format.ts` 共享模块）。需要富文本/成稿操作时点「详细编辑」打开既有 `OutlineNodeEditor` 抽屉。
- **徽章行**：写作状态（`OutlineStatus` 既有三态色点）；`gen==='ai'` 时显示 ✦ AI 小徽标（样式对标 WorldTreePanel 的 sourceBadge）；成稿态显示章节序号（`chapter_id` → `第N章`，按大纲序）；发布态/线差异徽章来自《分支设计》chain API（W3 接入）。
- **节点右键/悬浮菜单**：添加下一个（同 §5.2）、从此生成脉络（§5.3）、成稿（AI 扩写，既有链路）、从此分叉世界线（《分支设计》fork API，`fork_node_id` = 本节点 id）、插入候选支线（手动写一条 `veins[]` 候选）、删除节点（复用 `removeNode`；有 `chapter_id` 绑定的节点沿用 OutlinePanel 现有删除确认——章节+节点+内容一并入回收站的语义不变）。

### 5.2 添加下一个控件（`AddNextControl`）——一个控件两态

链尾（以及每个叶节点右侧）渲染胶囊控件：

```
      ┌─────────────┬───┐
      │  ＋ 下一节点 │ ✦ │
      └─────────────┴───┘
       左半：普通添加     右半：AI 创建
```

- **左半（手动）**：点击即在链尾追加空节点并进入标题编辑态；`Enter`（在标题输入中按 Tab/Enter 依快捷键方案，§9.3）跳简介。
- **右半（AI 创建）**：✦ 图标点击 → 就地生成：锚节点右侧先出现 shimmer 占位节点（临时 toast「AI 正在构思下一章…」），返回后**直接创建节点并进入编辑态**（单节点所见即所得，不满意直接删，无需确认弹窗）；失败则占位消失 + 错误 toast，锚节点原样保留。
- **门禁联动（核心规则）**：锚节点 `title` 与 `stripTags(summary)` 任一为空 → 左右两半都禁用（左半 tooltip「先完成当前节点的标题与简介」，右半 tooltip「AI 需要当前节点内容作为上下文」）。这从交互上落实「必须填写/生成了标题+简介才能添加下一个」——AI 生成的节点天然带标题+简介，所以 AI 链路不会被门禁卡住。
- 键盘：选中节点后 `Enter`=左半，`Shift+Enter`=右半（§9.3）。

### 5.3 从此生成脉络（`VeinDialog`）——批量 AI 生成

节点菜单「从此生成脉络」弹出对话面板，形态对标 StoryWorkflowPanel：

```
┌─ 从《节点X》生成脉络 ────────────────────────────────┐
│ 生成数量  ├───────────●──────────┤ 5 节点   ← 滑杆 2–10 │
│ 方向提示（可选）[在这条线上，主角开始怀疑导师……_______________] │
│ 线索库  ☑ 大纲  ☑ 记忆  ☐ 伏笔   ← 复用 CLUE_LIBRARIES 勾选卡 │
│ 生成目标  ○ 顺延当前线（追加到链上）  ○ 存为候选支线（挂在本节点下）│
│                                  [取消]  [生成预览]      │
└──────────────────────────────────────────────────────────┘
```

- **滑杆**：2–10 个节点，默认 5（对标 `chapter_count` 滑杆的交互与样式）。
- **方向提示**：一句话自由输入（可空），作为生成的额外指令注入。
- **线索勾选**：复用线索勾选卡交互与摘录构建（抽共享模块，见 §7.1）；库为空时对应项不可勾选，与 StoryWorkflowPanel 行为一致。
- **生成目标两态**：
  - **顺延当前线**（默认）：生成的 N 个节点插入锚节点之后（链中间插入则后移既有节点，大纲序自动保持）；先渲染**预览态**——虚线节点链挂在锚点右侧（不落库），卡片底部 `[换一批] [采纳] [放弃]`；采纳 = 写入 acts 并走保存链路。这是 story 流水线「StagePayload 预览 → 作者确认 → 采纳落库」范式的轻量复刻。
  - **存为候选支线**：生成的 N 个节点写入锚节点的 `veins[]`（画布上以虚线子链呈现，默认折叠，可展开/提升/删除）；不参与门禁、不绑章节、不影响链序。提升 = 把候选按序插入主链锚点之后并从 `veins[]` 移除（走既有 `addNode/updateNode` 动作序列）。
- 预览态数据只存 `canvas-store`（内存），刷新即弃——与"采纳才落库"的边界一致。
- 生成过程中锚点与预览区 shimmer；`AbortController` 支持取消；换一批 = 同参重调。

### 5.4 世界线联动（挂接《分支设计》，不重复实现）

- 画布顶栏世界线切换器与编辑器共用一个组件（抽公共 `WorldlineSwitcher`）；切换线 = 调 checkout → 重载大纲徽章数据（结构本身全线共享，画布内容不变，徽章/差异态变化）。
- 节点菜单「从此分叉世界线」：预填《分支设计》§4.3 fork 表单（`fork_node_id` = 本节点 id），成功后 toast + 顶栏线计数刷新。
- 「存为候选支线」的候选在适当时机可再走「落地为世界线」：候选提升为主链节点后，从提升后的锚点节点 fork（《分支设计》语义：线分叉的是**内容**不是结构）。

## 6. 完整性门禁（避免空内容节点）

### 6.1 门禁定义

`nodeComplete(n) := n.title.trim() ≠ '' && stripTags(n.summary).trim() ≠ ''`

- 作用点 1（画布交互）：§5.2 控件禁用；§5.3 入口仅对 complete 节点可见。
- 作用点 2（AI 链路）：单节点与脉络生成请求必须携带锚节点 title+summary（不完整时后端 422，前端其实已禁用，此处防御）。
- 作用点 3（服务端不变式）：`PUT /novels/:id/outline` 保存时校验——**同一幕 nodes 数组中，除末节点外的每个节点必须 complete**（`ErrOutlineNodeIncomplete`，422，响应带第一个违规节点的 `act_id/node_id` 供前端定位高亮）。该不变式与"在中间节点后插入"操作自洽：手动/AI 插入的来源节点必然 complete（门禁 1/2 保证）；拖拽排序把不完整节点移到链中间会被 422 拦下，前端提示"请先补全该节点或移到链尾"。
- `veins[]` 候选不参与门禁（候选允许半成品）。
- OutlinePanel（列表视图）同步吃作用点 3 的服务端校验（两编辑器一个约束，避免画布收起后列表写出违规结构）。

### 6.2 服务端校验实现要点

`novel_doc_service.UpdateOutline` 在 `validateDocPayload` 后新增 `validateChainCompleteness(acts)`：walk acts → nodes，对 `i < len(nodes)-1` 的节点做 complete 判定（summary 是 HTML，strip 标签后判空——复用 `StoryWorkflowPanel.tsx:216` 同款 stripTags 逻辑在 Go 侧实现）。`veins` 键跳过。Agent 的 `save_outline` 工具同路径落库，自动受同一门禁约束（Agent 生成天然带标题+简介，正常不受影响）。

## 7. Agent 生成链路（深度结合的三条通道）

### 7.1 共享底座：`clues-client.ts`（复用全本创作的线索机制）

把 `StoryWorkflowPanel.tsx:207-240` 的三库摘录构建（fetchOutline/fetchMemory/listForeshadows → 格式化 → 1200 字符截断）抽为 `web/src/services/clues-client.ts`：

```ts
export async function buildClueExcerpts(novelId: number):
  Promise<Record<StoryOverviewClueKind, string>>;   // 三库摘录
export function pickClues(on: Record<StoryOverviewClueKind, boolean>,
  excerpts: Record<StoryOverviewClueKind, string>): StoryOverviewClue[];
```

StoryWorkflowPanel 与画布 `VeinDialog` 共用（"复用不少代码"的主要落点）。

### 7.2 直连通道（默认）：两个结构化 AI 端点

对标 `expand-outline` 的代理模式（`ai_handler.go:829-840` → `proxyBound("/api/ai/...")`），ai-service 新增两个场景化端点：

| 端点 | 入参 | 出参 |
|------|------|------|
| `POST /api/v1/ai/canvas-next-node` | `novel_id, anchor: {title, summary}, direction_hint?, clues[], worldline: {name, fork_point_label?, description?}, recent_chain: [{title, summary}] ×≤5` | `{ node: {title, summary} }` |
| `POST /api/v1/ai/canvas-vein` | 同上 + `count: 2-10, target: 'chain'\|'candidate'` | `{ nodes: [{title, summary}] ×count }` |

- **上下文组装（Go 侧）**：recent_chain 取锚节点在链上的前驱窗口（大纲序）；worldline 块来自《分支设计》数据（激活线名、分叉点、线描述）——这是"世界线感知生成"的关键：在《复仇线》上生成，AI 明确知道要写分歧后的走向。
- **ai-service 侧**：新 scene `canvas_node`（复用 scenes.py 的场景装配与线索注入格式，`clues` 三库摘录的注入格式与 story-overview 一致）；结构化 JSON 输出（title ≤30 字、summary 2–4 句），失败fail-fast 返回错误（不做本地 mock 兜底——沿用 OutlineNodeEditor 扩写"失败如实报错"的既定原则）。
- **落库**：前端拿到 JSON 后走 `outline-store`（`addNode`/批量插入 + `gen:'ai'`/`vein_id` 标记）→ 既有保存链路（乐观锁 + agent_auto 快照自动发生）。
- 明确**不走 task_engine**：单次 LLM 调用（≤10 节点），秒级返回；进度用画布内联 shimmer + 临时 toast（备忘录 L61），AbortController 可取消。

### 7.3 Agent 深度通道（并行能力，零新增后端）

画布顶栏「让 Agent 规划」按钮：预填指令到 AI 对话（复用 WorldTreePanel 的 `inkbloom:show-chat` / `inkbloom:chat-draft` 事件总线），指令模板携带锚点上下文与诉求（如"从《XX》后生成 5 个节点的脉络，参考记忆库"），Agent 经既有 `save_outline` 工具落库。落库结果在画布重拉后可见（agent_auto 大纲快照已保底可回滚）。此通道适合"放手让 Agent 规划一整幕"，直连通道适合"精确的下一步"。

## 8. 前端组件设计

### 8.1 组件树

```
CanvasOverlay（全屏壳；ESC/缩放/平移/顶栏底栏）
├─ WorldlineSwitcher（自《分支设计》W2 抽出共用）
├─ CanvasTree（布局 + 连线渲染）
│  ├─ CanvasActNode（幕节点：折叠/展开、右键菜单：加幕/改名/删幕）
│  ├─ CanvasNode（§5.1；含 AddNextControl 与脉络候选子链渲染）
│  │  └─ VeinPreviewChain（预览态虚线链）
│  └─ CanvasEdge（SVG 贝塞尔连线）
├─ VeinDialog（§5.3）
└─ CanvasNodeDrawer → 复用 OutlineNodeEditor（详细编辑/成稿）
```

### 8.2 布局与渲染（自研，不引新依赖）

- **布局**：横向逻辑图（根左、子右）。数据是"幕 → 线性节点链"的受限树，自研 flex 列布局 + 量测即可，不必引入 cytoscape（canvas 渲染，就地编辑/HTML 徽章/无障碍成本高）或 react-flow（重依赖，引入收益低）。节点卡片用绝对定位（坐标由布局函数给出），连线用单层 `<svg>` 画三次贝塞尔。
- **视口**：容器 `transform: translate+scale`；滚轮缩放（0.4–2.0，Ctrl+滚轮；普通滚轮平移）、空格/中键拖拽平移、「适应画布」按钮；视口存 localStorage（`inkbloom-canvas-viewport-{novelId}`）。
- **折叠**：幕与节点都可折叠（`canvas-store` 内存态）；折叠后连线汇聚到折叠桩。
- **性能阈值**：节点 ≤ 300 全量渲染；超过后非可视区节点渲染为轻量占位卡（IntersectionObserver），标题简介照常可读。单书大纲实际规模（≤ 数百节点）下无需虚拟滚动库。
- **样式**：沿用现设计语言（`bg-white/5 border-white/8 rounded-lg`、violet 强调色、lucide 图标）；AI 徽章样式对标 WorldTreePanel 的 `sourceBadge`（fuchsia 系）。

### 8.3 键盘快捷键（画布聚焦时）

| 键 | 行为 |
|----|------|
| `Tab` | 在选中节点后添加下一节点（手动，等价左半） |
| `Enter` | 选中节点进入标题编辑；编辑中 Enter 提交并聚焦简介 |
| `Shift+Enter` | AI 生成下一节点（等价右半） |

## 9. 边界与风控

| 风险 | 对策 |
|------|------|
| 画布与 OutlinePanel/Agent 并发写大纲 | 既有 `expectedVersion` 乐观锁：保存 409 → toast + 重拉本地覆盖（本地未保存编辑先入 localStorage 草稿防丢） |
| AI 生成质量差/失败 | 直连通道 fail-fast + 「换一批」重试；方向提示必填引导（可空但 placeholder 鼓励）；token 消耗遵循备忘录"最小 tokens"：单节点 ≤600 token 级提示词，脉络一次调用而非逐节点循环 |
| 链中间插入导致既有节点后移 | 插入预览高亮受影响区间；大纲序 rank 由既有 sync 机制收敛（《分支设计》§4.6 同路径） |
| 候选支线堆积 | `veins[]` 每节点上限 5 条；超出提示先清理 |
| 门禁误伤（历史数据本就有中间空节点） | 校验**只对新写入生效**：读入时不改数据，用户编辑到该幕并保存时才触发 422 + 定位提示（渐进收敛，不做批量迁移） |
| 大数据量卡顿 | §8.2 性能阈值；布局计算 useMemo + 节点量测缓存 |
| 桌面端（Electron） | 纯前端能力 + 既有 AI 代理，无新系统依赖；后端不可用时画布只读（保存失败已有 localStorage 兜底语义） |

## 11. 总验收清单（用户视角的一句话检验）

1. 从世界线切换器进入画布，像用 Xmind 一样缩放、折叠、拖看整本书的章节树；每章节点就地改标题、写简介。
2. 链尾胶囊"＋下一节点"，左边手写、右边点 ✦ 让 AI 接着写；不写完当前章的标题+简介，两个按钮都是灰的。
3. 在关键章节右键"生成脉络"，拉滑杆选 5 章、勾上记忆库和伏笔，预览一串虚线新节点——换一批直到满意，采纳后它们进入大纲，之后照常成稿、发布、分叉世界线。
4. 也可以一键"让 Agent 规划"，对话里的 Agent 直接把一整幕的大纲写进画布；不满意，大纲快照一键回滚。
