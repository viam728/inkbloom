# E4 阅读器与一键发布（A16–A19）施工计划

## 目标

作者一键发布作品与章节；读者免登录访问 `/read/:slug` 阅读。四张新表 + 两个新服务 + 前端阅读器。

## 已核实的关键事实（决定了方案走向）

| 事实 | 影响 |
|---|---|
| **编辑器只写 `Chapter.Content`（HTML 字符串）**，`ContentJSON` 生产上恒为空。`TipTapEditor.tsx:178` 用 `ed.getHTML()`，`editor-store.ts:51` 只 `PUT {content}`；前端无任何写 `content_json` 的路径 | 任务书"优先读 ContentJSON"的做法会拿到空值。发布快照的权威正文就是 HTML |
| **`export_handler.go:57-64` 有既有 bug**：ContentJSON 为空时把 HTML 字符串塞进 TipTap text 节点，导出结果会显示成 `<p>正文</p>` 字面量 | 发布链路不能踩同一个坑；顺手一并修 |
| `Contentsafety.Checker` 目前只在 `handler/aigc_handler.go:121-131` 调用（handler 层，`WithContentSafety` 注入），service 层无先例 | A17 是首次在 service 层用，需新增装配路径 |
| 限流：`ScopeAnon` 5 req/s **按路由分桶**；`ScopeAPI` 20 req/s **按 uid 共享桶**（`middleware/ratelimit.go:52-53`） | 公开阅读用 ScopeAnon，否则匿名读流量会和其它 API 互相饿死 |
| `TokenLedger` 无 `novel_id`/`chapter_id`，`reason='ai_call'` 只能判到用户级 | AIInspired 需章节级主判据 |
| 前端无 react-router，路由在 `App.tsx:127-139` IIFE 正则匹配，无 popstate 监听 | 章节切换沿用整页刷新 |
| Tailwind v4，`prose` 不可用，但 `index.css:147-250` 的 `.tiptap` 排版样式可复用 | 阅读器容器套 `tiptap` 类名即可零成本复用排版 |

## 五项架构决策

1. **渲染路径：服务端返回 HTML。** `Content` 本来就是 TipTap 的 `getHTML()` 产物，标签正好命中 `.tiptap` 选择器。前端 `dangerouslySetInnerHTML`，容器加 `tiptap` 类名。不走 JSON 路（需新装 `@tiptap/html` 且必失真），不拉只读 TipTap（150KB+ 对免登录首屏不划算）。
2. **XSS：自研白名单净化器**（用户已选）。新包 `internal/pkg/contentsanitize`，用已在 go.mod 的 `golang.org/x/net/html` 写约 120 行，白名单 `p/h1-h3/ul/ol/li/blockquote/code/pre/br/strong/em/a[href]/img[src]`，发布写入与读取时双重净化。**禁用正则做净化。**
3. **限流：ScopeAnon。** 一次阅读会话约 1–3 req/s（作品+目录+章节三条路径各自分桶），5 req/s 足够。首版不动全局配额表。
4. **阅读进度：** 滚动容器 rAF + 150ms trailing 节流算 `position = scrollTop/(scrollHeight-clientHeight)`。上报三时机：停止滚动 1s / 距上次 >10s 且位移 >0.02 / `visibilitychange→hidden` 或 `pagehide`。游客进度存 localStorage，登录后首次进入补报（进度表按 user_id 唯一索引，匿名写不进去）。服务端 `clause.OnConflict{Columns:[user_id,work_id]}` 做 upsert，**PG/SQLite 双模式都要测**（C11）。
5. **章节切换：整页刷新。** 加 popstate 等于引入第二套路由真相，必出幽灵 bug。`nginx.conf:11-13` 与 `http.go:159-181` NoRoute 已保证深链不 404。

**AIInspired 判定：** 主判据 `chapter_versions.kind='ai_rewrite'`（A03 已在 AI 改写前自动落快照，精确到章节，命中现有 `idx_cver_chapter`）；兜底 `token_ledger.reason='ai_call'`（用户级）。DTO 附带 `ai_inspired_source: "chapter"|"author"|""`。注释写明局限：用户级判据会把纯手写作品误标。

## A18 · 公开阅读 API

**新增** `internal/handler/reader_handler.go`、`internal/service/reader_service.go`

**匿名组** 插在 `http.go:231` 之后、236 行 events 之前（**必须早于 248 行 authMiddleware**）
```go
if h.Reader != nil {
    readerGroup := engine.Group("/api/v1/read")
    if h.RateLimiter != nil {
        readerGroup.Use(h.RateLimiter.Scope(middleware.ScopeAnon))
    }
    readerGroup.GET("/works/:slug", h.Reader.GetWork)
    readerGroup.GET("/works/:slug/chapters", h.Reader.ListChapters)
    readerGroup.GET("/chapters/:pid", h.Reader.GetChapter)
}
```

**登录态三条** 挂在 `api` 组内：`GET/PUT /read/progress`、`POST /read/follows`、`DELETE /read/follows/:wid`

**必改**：`middleware/require_writable.go:19-33` 的 `writableExemptPrefixes` 追加 `"/api/v1/read"`。否则未登录或订阅过期时 `PUT /read/progress` 会返 402，前端弹出订阅弹窗（api-client 402 是唯一会自动弹窗的状态码）。

**visibility 过滤**：`private` 直接 404（不返空数据，避免探测）；`unlisted` 仅当 URL 带正确 slug 放行；定时未到点 404。

## 验收（可执行，不是"应该能过"）

1. local 与 PG 各启动一次 → 四表均存在
2. 同标题发布两次 → 第二次 slug 带 `-2`，无重复
3. 发布一章 → `PUT /chapters/:id {content:"<p>改了</p>"}` → `GET /api/v1/read/chapters/:pid` 仍返回旧正文
4. 净化器单测：`<script>alert(1)</script>`、`<img onerror=...>`、`javascript:` 链接均被剥离，正常 `p/h2/blockquote` 保留
5. 定时 `scheduled_at = now()+1h` → 匿名与登录态均 404；到点后 200。`EXPLAIN` 确认走 `idx_pc_work_pos`
6. 无 Authorization curl `/read/works/<slug>` → 200；private → 404；`POST /read/follows` → 401
7. 连发 10 次 → 前 5 个 200，之后 429
8. 订阅置 dormant → `PUT /read/progress` 仍 200（豁免生效），前端无订阅弹窗
9. 隐身窗口访问 `/read/<slug>` 不跳登录；改字号刷新后保持；DevTools 确认顶层块有递增 `data-block-index`
