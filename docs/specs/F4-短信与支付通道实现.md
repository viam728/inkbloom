# F4 · 短信与支付通道实现（无商户资质，仅实现代码，不写自动化测试）

## 目标

把 `sms.ProdProvider` 与 `payment.AlipayProvider/WechatProvider` 从 TODO 占位实现为**可配置、可直接对接真实渠道**的代码；同时堵掉已确认的**支付回调无鉴权无验签**漏洞。

## 已核实的关键事实（决定方案走向）

| 事实 | 影响 |
|---|---|
| `http.go:326-331` 的 `payGroup` 直接挂在 `engine` 上，**不在 `api`（auth）group 内**（`api` 在 `:354` 才创建） | `POST /api/v1/payment/notify/:channel` **完全公开、无鉴权、无验签** —— 知道订单号即可白嫖订阅。**P0，本轮必须修** |
| `payment_service.go:68` 调 `provider.Prepay(ctx, "", ...)` —— **outTradeNo 传空**，且 `newOutTradeNo()` 在 `:81` 才生成 | 订单号必须在 Prepay 之前生成，否则真实渠道拿不到商户单号。**顺序 bug** |
| `payment_service.go:126` 硬编码 `MarkPaid(..., "SANDBOX-"+order.OutTradeNo, ...)` | 真实渠道需回填渠道流水号 |
| `config.go` **无 SMS 配置段**；`main.go:152` 硬编码 `sms.NewDevProvider(logger)` | 需新增配置段 + 工厂函数 |
| `config.go:258` cloud 模式已有「拒绝占位密钥」的先例 | 短信/支付沿用同一 fail-fast 风格 |
| 内测期 sandbox 渠道若对 cloud 开放 = 任何人免费续订 | sandbox **必须限定 local 模式** |

## 决策

1. **不引入第三方 SDK**：阿里云 POP 签名（HMAC-SHA1）与腾讯云 TC3-HMAC-SHA256 均可纯 `crypto/hmac` + `net/http` 实现；支付宝 RSA2 与微信 v3 用 `crypto/rsa`/`crypto/sha256`/`crypto/aes`（GCM）标准库即可。避免 go.mod 膨胀。
2. **接口扩展而非破坏**：`Provider.Prepay` 返回 `*PrepayResult`（携带 `CodeURL`/`PayURL`/`Params`）；新增 `VerifyNotify(*http.Request)`。Sandbox 实现返回空 result，调用方按 `Channel()=="sandbox"` 分流。
3. **验签缺失即拒绝**：未配置真实凭据的渠道，其 notify 路由**不注册**（而非注册后返回错误），减少攻击面。
4. **不写自动化测试**（用户明确要求）；但提供手动验证清单，且所有签名/验签代码必须可被 `go build` 与 `go vet` 通过。

## F4-3 支付接口扩展

**改** `internal/pkg/payment/provider.go`
```go
type PrepayResult struct {
    Channel        string            // alipay | wechat
    CodeURL        string            // 二维码链接（微信 native code_url / 支付宝 qr_code）
    PayURL         string            // 跳转支付页（支付宝 page pay）
    Params         map[string]string // 客户端拉起支付所需参数
}

type Provider interface {
    Channel() string
    Prepay(ctx context.Context, outTradeNo string, amountCents int, subject string) (*PrepayResult, error)
    // VerifyNotify 校验渠道回调签名的真实性，返回商户单号与渠道流水号。
    VerifyNotify(r *http.Request) (outTradeNo string, channelTradeNo string, err error)
}
```
- Sandbox 实现：`Prepay` 返回空 result + nil；`VerifyNotify` **仅 local 模式放行**（返回 body 里的 `out_trade_no`），cloud 返回 `ErrChannelUnavailable`

## F4-4 支付宝 Provider（代码 only）

**新增** `internal/pkg/payment/alipay.go`
- `NewAlipayProvider(cfg AlipayCfg, logger) (*AlipayProvider, error)` —— 解析 PKCS1/PKCS8 商户私钥与支付宝公钥
- `Channel() == "alipay"`
- `Prepay` —— `alipay.trade.precreate`（扫码），业务参数 `out_trade_no/total_amount/subject`；公共参数 `app_id/method=alipay.trade.precreate/format=JSON/charset=utf-8/sign_type=RSA2/timestamp/version=1.0/biz_content`
- **签名**：待签串 = 除 `sign` 外参数按 key 升序 `k=v&` 拼接（值不做 URL 编码，按支付宝规范）→ `rsa.SignPKCS1v15(SHA256, 私钥)` → base64
- 响应 `alipay_trade_precreate_response.code == "10000"` 时取 `qr_code` 填入 `CodeURL`；失败返回带 `sub_msg` 的错误
- `VerifyNotify(r)` —— 解析 `r.Form`（`application/x-www-form-urlencoded`），取 `sign` 与 `sign_type`；待验签串 = 剩余参数按 key 升序拼接；`rsa.VerifyPKCS1v15(支付宝公钥, SHA256)`；从 `out_trade_no`/`trade_no` 取值；`trade_status` 为 `TRADE_SUCCESS`/`TRADE_FINISHED` 才算成功

## F4-5 微信支付 Provider（代码 only）

**新增** `internal/pkg/payment/wechat.go`
- `NewWechatProvider(cfg WechatCfg, logger) (*WechatProvider, error)` —— 解析商户 API 证书私钥
- `Channel() == "wechat"`
- `Prepay` —— Native 下单 `POST https://api.mch.weixin.qq.com/v3/pay/transactions/native`；body `{appid, mchid, description, out_trade_no, notify_url, amount:{total, currency:"CNY"}}`
- **签名**（v3）：`HTTP方法\nURL路径\n时间戳\n随机串\nbody\n` → `rsa.SignPKCS1v15(SHA256, 私钥)` → base64；`Authorization: WECHATPAY2-SHA256-RSA2048 mchid="...",nonce_str="...",signature="...",timestamp="...",serial_no="..."`
- 成功取 `code_url` 填 `CodeURL`
- `VerifyNotify(r)` —— 校验 `Wechatpay-Timestamp` 在 5 分钟内；待验签串 `时间戳\n随机串\nbody\n`；用**平台证书公钥**验 `Wechatpay-Signature`；`resource` 用 APIv3 密钥做 **AES-256-GCM** 解密（`nonce/tag=associated_data/ciphertext`）得到 `out_trade_no`/`transaction_id`
- 平台证书公钥从 `Wechatpay-Serial` 对应的缓存中取；**首次启动需 `GET /v3/certificates` 拉取**（实现拉取与内存缓存，30 分钟刷新）

## 手动验证清单（不写自动化测试，按此逐条人工核对）

**短信**
1. 不配置短信凭据 → 服务正常启动，走 DevProvider；日志中**无** 6 位验证码明文
2. 配置阿里云凭据（可用任意占位值）→ 启动通过；调发送接口返回明确的渠道错误（如 `InvalidAccessKeyId`），证明请求已按签名规范发出且未 panic
3. 同 2 验证腾讯云：返回 `AuthFailure.SignatureExpire` 或 `InvalidParameter` 类错误，而非本地签名构造异常

**支付**
4. 空配置 → `/api/v1/payment/notify/alipay` 返回 404（路由未注册）
5. 配置占位支付宝凭据 → 下单返回 `qr_code` 字段（或渠道错误），订单状态为 `created` 而非 `paid`
6. `POST /api/v1/payment/notify/alipay` 带**伪造** body → 返回 **401**，订单未变成 paid
7. cloud 模式下 sandbox 下单 → 返回「通道未开放」；local 模式 → 正常即时到账
8. `go build ./...`、`go vet ./internal/...` 通过；`gofmt -l` 无输出
